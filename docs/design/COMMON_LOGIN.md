# 共通 ログイン・パスワード再設定・確認コード — 画面資料

## 位置づけ

2026-10-23のKenの承認を基に、Master・Client共通のログインまわり5画面の構成・項目・状態を整理する画面資料。業務仕様の正は[SPECのログインの確定事項](../SPEC.md#ログインの確定事項)とし、本資料には画面制作に必要な前提だけをまとめる。

「確定」はSPECの決定事項、または本資料に明記したKenの決定、「仮」はKenが仮のままでよいとした文言、「案」は画面で調整・決定する内容、「未確定」は今後の確認事項とする。

画面はMaster・Clientで共通のため、資料名は`COMMON_LOGIN.md`とする（共通の画面資料は`COMMON_画面名.md`。[docs/README.md](../README.md)）。見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、実装時の書き方は[実装連携ガイド](../coding/IMPLEMENTATION_REFERENCE.md)を参照する。

バックエンドへの申し送り（アカウントの作り方・セッション・確認コードの実装など「バックエンドで決めてほしいこと」を含む）は、あとで`coding/`にまとめる。今回は書かない。

## 確定している前提（2026-10-23、Kenの承認）

以下は[SPECのログインの確定事項](../SPEC.md#ログインの確定事項)の要約。

- ログインIDはメールアドレス。アカウントは管理画面では作らず、保守会社（Ken）が作る。Masterに「アカウント管理」の画面は作らない
- 初めて使うときは、管理者がアカウントを作ったあと再設定メールを送り、本人が「新しいパスワードの設定」で決める
- 画面はMaster・Clientで共通。違いは[Master・Clientの違い](#masterclientの違い)の表だけ
- Masterだけ、パスワードが合ったあとに確認コード（6桁・メール）を入力する
- 未ログインで管理画面を開いたらログイン画面へ、ログイン後は開こうとしていたページへ戻す。直接ログインしたときの行き先はClientが受注一覧、Masterは未定（申し送りで仮置き）

### 上部の表記（確定：2026-10-23、Kenの決定）

ログイン後のヘッダーとそろえ、サービス名と管理画面名を縦線で区切る。

- Client：「熊日モール｜パートナー管理画面」
- Master：「熊日モール｜管理画面」

ページ見出し（`h1`）は画面名（「ログイン」「パスワードの再設定」「新しいパスワードの設定」「確認コードの入力」）とする。`title`は「画面名｜熊日モール パートナー管理画面」（Masterは「熊日モール 管理画面」）。

### ログイン後のClientのヘッダー（確定：2026-10-23、Kenの決定）

- 既存のヘッダー（`shop-partner/includes/inc_header.php`）の`.admin-name`を「{パートナー名} 管理画面」にする。モックのパートナー名は「熊日メディアコム」
- 長い名前は1行で省略（`text-overflow: ellipsis`）し、`title`属性で全文を出す。ヘッダーの高さは変えない
- ログアウトは既存の`.box-actions`のform・buttonを使う。置き場所は変えない

## 項目

### 1. ログイン

| 項目 | 部品 | 属性・補足 |
|---|---|---|
| メールアドレス | `input type="email"` | `name="email"`、`autocomplete="username"`、`autocapitalize="none"`、`spellcheck="false"` |
| パスワード | `input type="password"`＋表示切り替えボタン | `name="password"`、`autocomplete="current-password"` |
| ログイン状態を保持する | チェックボックス（Clientのみ） | `name="remember" value="1"`、初期オフ。Masterには出さない（二段階認証の抜け道になるため） |
| ログイン | 主ボタン（幅いっぱい） | 送信中は無効にして「ログイン中…」 |
| パスワードを忘れた方 | リンク | 再設定の申し込みへ |

### 2・3. 再設定の申し込み・送信しました

| 項目 | 部品 | 属性・補足 |
|---|---|---|
| 説明文 | `p` | 「登録しているメールアドレスを入力してください。パスワードを再設定するためのメールを送ります。」（案） |
| メールアドレス | `input type="email"` | `name="email"`、`autocomplete="username"` |
| 再設定のメールを送る | 主ボタン | 送信中は無効にして「送信中…」 |
| ログイン画面に戻る | リンク | |

送信後はフォームを出さず、上部に「登録があれば、再設定のメールを送りました。」（`role="status"`）と、補足「メールに記載されたリンクから、新しいパスワードを設定してください。届かない場合は、メールアドレスを確かめてもう一度お申し込みください。」（案）、「ログイン画面に戻る」を表示する。

### 4. 新しいパスワードの設定

| 項目 | 部品 | 属性・補足 |
|---|---|---|
| 新しいパスワード | `input type="password"`＋表示切り替えボタン | `name="password"`、`autocomplete="new-password"`。補助文「8文字以上で入力してください」を`aria-describedby`で関連付ける |
| 新しいパスワード（確認） | `input type="password"`＋表示切り替えボタン | `name="password_confirmation"`、`autocomplete="new-password"` |
| パスワードを変更する | 主ボタン | 送信中は無効にして「変更中…」 |
| ログイン画面に戻る | リンク | |

再設定のトークンとメールアドレスは`type="hidden"`で送る制作例とする（Laravel標準の再設定フォームに合わせた仮置き。送り方はバックエンドで決める）。

### 5. 確認コードの入力（Masterのみ）

| 項目 | 部品 | 属性・補足 |
|---|---|---|
| 送り先 | `p` | 「k***@example.jp にコードを送りました。メールに記載された6桁のコードを入力してください。有効期限は10分です。」（伏せ方と文は案） |
| 確認コード | `input type="text"` 1つ | `name="code"`、`inputmode="numeric"`、`autocomplete="one-time-code"`、`maxlength="6"` |
| 確認する | 主ボタン | 送信中は無効にして「確認中…」 |
| コードを再送する | リンクの見た目の`button`（別のform） | メールを送る操作のため`a`ではなくPOSTの`button`にする。送信から60秒は`disabled`にし、横に「あと〇秒で再送できます」を出す。0秒で押せるようにし、読み上げ用に1回だけ「コードを再送できます」と知らせる。残り秒数は毎秒読み上げない |
| ログイン画面に戻る | リンク | |

## エラーと状態

| 状態 | 画面 | 表示 | 文言 |
|---|---|---|---|
| 未入力・形式の誤り | 全画面 | 各欄のすぐ下（`.form-error`・`aria-invalid`・`aria-describedby`）。最初の誤りの欄へフォーカス | 「メールアドレスを入力してください」「メールアドレスの形式で入力してください」「パスワードを入力してください」「8文字以上で入力してください」「パスワードが一致しません」「確認コードを入力してください」「6桁の数字で入力してください」 |
| 認証の失敗 | ログイン | フォーム上部に1つだけ（`role="alert"`）。どちらが違うかは出さない。メールアドレスは残し、パスワードは空にしてパスワード欄へフォーカス | 「メールアドレスまたはパスワードが正しくありません」 |
| 5回続けて失敗 | ログイン | 約1分止めて、フォーム上部に表示。入力欄・ボタンは無効にしない。アカウントのロックはしない | 「しばらくしてからもう一度お試しください」 |
| パスワードの変更完了 | ログイン | 上部に`role="status"` | 「パスワードを変更しました」 |
| 確認コードを5回間違えた | ログイン（Master） | ログイン画面からやり直し。上部に表示 | 「確認コードの入力に続けて失敗したため、もう一度ログインしてください」（仮） |
| 確認コードが違う | 確認コード | 欄のすぐ下 | 「確認コードが正しくありません」（案） |
| 確認コードの期限切れ | 確認コード | フォーム上部。再送は押せる状態 | 「確認コードの有効期限が切れました。コードを再送してください」（仮） |
| 再送した | 確認コード | 上部に`role="status"`。残り秒数を60秒から数え直す | 「コードを再送しました。前のコードは使えません。」（案） |
| 再設定リンクの期限切れ・使用済み | 新しいパスワードの設定 | フォームを出さず、上部に表示し、申し込み画面へのリンクを置く | 「このリンクは使えません。もう一度再設定を申し込んでください」（仮） |

- 確認コードの有効期限は10分。再送すると前のコードは無効
- エラーの見た目は既存の`.error-summary`（赤い枠の白い箱）、完了の知らせは`.save-status`（左にブランド色の線）を使う

## Master・Clientの違い

| 項目 | Client | Master |
|---|---|---|
| 上部の表記 | 熊日モール｜パートナー管理画面 | 熊日モール｜管理画面 |
| ブランド色（線・文字・フォーカス） | 緑（`#097141`） | 青（`#0D679C`、仮値） |
| ログイン状態を保持する | あり（初期オフ） | 出さない |
| 確認コードの入力 | なし | パスワードが合ったあとに表示 |
| ログイン後の行き先（直接ログインしたとき） | 受注一覧 | 未定（申し送りで仮置き） |

## アクセシビリティ（案）

- 表示切り替えボタンは名前を「パスワードを表示」に固定し、`aria-pressed`で状態を伝える。アイコンはLucideの`eye`（隠している）／`eye-off`（表示中）を切り替える。`aria-controls`で欄を参照し、ボタンは44px角。JSが使えないときはボタンを出さない
- 送信の前にパスワード欄を`type="password"`へ戻す
- Edgeの独自の表示ボタン（`::-ms-reveal`）は二重になるため消す。SafariのパスワードのAutoFillのボタンは消さない
- 送信中のボタンは`disabled`にし、ブラウザの「戻る」で戻ったとき（`pageshow`の`persisted`）は元に戻す

## 制作記録（2026-10-23）

### ファイル・読み込み

PHPのテンプレートは`shop-partner/`に1つずつ置き、Masterは`shop-master/`の同じ名前のPHPで`$adminType = 'master'`を入れて読み込む。CSS・JSは相対パスで読むため、MasterのURLで開くとMasterのファイルを読む。確認コードはMasterだけなので`shop-master/login-code.php`に単独で置く。

| 種類 | Client | Master |
|---|---|---|
| ログイン | `shop-partner/login.php` | `shop-master/login.php`（読み込むだけ） |
| 再設定の申し込み・送信しました | `shop-partner/password-forgot.php` | `shop-master/password-forgot.php`（読み込むだけ） |
| 新しいパスワードの設定 | `shop-partner/password-reset.php` | `shop-master/password-reset.php`（読み込むだけ） |
| 確認コードの入力 | — | `shop-master/login-code.php` |
| 共通Sass | `shop-partner/assets/scss/common.scss`（既存） | `shop-master/assets/scss/common.scss`：Clientの`common.scss`を`@use`し、ブランド色だけMasterの値で上書き |
| ログインのSass | `shop-partner/assets/scss/login.scss` | `shop-master/assets/scss/login.scss`：Clientの`login.scss`を`@use`するだけ |
| JS | `shop-partner/assets/js/login.js` | `shop-master/assets/js/login.js`（Clientと同じ内容のコピー）、`shop-master/assets/js/login-code.js` |

CSSの読み込み順は`common.css`→`login.css`。JSは`login.js`（確認コードは`login.js`→`login-code.js`）を`</body>`直前で読む。`common.js`はサイドバー・検索用のため読み込まない。
