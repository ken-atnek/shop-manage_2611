# Client 顧客一覧 — 構成・項目の検討

## 位置づけ

2026-10-21のKenの決定を基に、Clientの顧客一覧を整理する画面資料。状態は「制作中」（2026-10-21、制作2回目完了）。電話番号列を外して末尾の詳細アイコンを採用し、制作用PHP・Sass・生成CSSで列幅等を調整した。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。見た目や未指定の検索条件を推測で確定しない。

顧客の定義・メールアドレスによる集約・閲覧範囲・集計条件は[SPECの顧客管理の確定事項](../SPEC.md#顧客管理の確定事項)を正とし、本資料には業務仕様を重複して定義しない。詳細画面は[顧客詳細](CLIENT_CUSTOMER_DETAIL.md)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、共通構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)を参照する。バックエンドへの確認は[QA No.11](../QA_BACKEND.md#no11-顧客管理のデータ閲覧範囲会員との関係)にまとめる。

## 確定している前提（2026-10-21）

- 対象はClient。顧客情報は閲覧のみで、編集操作を置かない
- サイドバーの「顧客管理」から本一覧へ入り、一覧と詳細の2画面で構成する
- 一覧は、Clientが閲覧できる購入者を1人につき1行で表示する。集約条件と閲覧範囲はSPECを参照する
- 氏名に使う「最新の注文」は、そのClientが閲覧できる注文（所属パートナーの店舗の注文）のうち最新のものとする。電話番号は一覧の列に置かず、検索対象に残し、顧客詳細で表示する
- 購入回数・購入金額の合計・最終購入日も同じ範囲の注文だけで算出し、ほかのパートナーの注文は表示にも集計にも使わない
- 検索は氏名・メールアドレス・電話番号のキーワードと、最終購入日の期間を使う
- 検索・日付入力は受注一覧・商品一覧の共通部品を利用する
- CSV書き出しは最初は置かない

## 項目

### 一覧の列（確定した構成・表示）

| 列 | 内容・表示 | 参照・補足 |
|---|---|---|
| 氏名 | Clientが閲覧できる注文のうち、最新の注文で確定した注文者の氏名 | 注文者情報の項目詳細は未確定 |
| メールアドレス | 注文者のメールアドレス | 顧客をまとめる条件はSPECを参照 |
| 購入回数 | Clientが閲覧できる範囲の注文を対象にした回数 | キャンセル・返品と数え方の単位は未確定 |
| 購入金額の合計（税込） | Clientが閲覧できる範囲の注文の合計金額を税込で表示 | キャンセル・返品を含めるかは未確定 |
| 最終購入日 | Clientが閲覧できる範囲で対象の顧客が最後に購入した日。日付だけの`time`要素 | 時刻は出さない |
| 詳細 | Lucide公式の`eye`リンク。読み上げ名・titleは「{氏名}さんの詳細」 | 商品一覧の編集列と同じ40pxの丸い操作領域 |

電話番号は顧客詳細で表示し、一覧のキーワード検索対象にも残す。購入回数・金額は右揃え・`tabular-nums`、金額は商品一覧と同じ`¥`＋3桁区切り。金額の見出しは「（税込）」をspanでまとめ、必要なときだけ「購入金額の合計」と「（税込）」の2行にする。

メールアドレスは`@`の直前に`wbr`を置き、それ以外の文字の途中では折り返さない。各部分だけでも列幅を超える場合は「…」で省略し、全文をtitleで確認する（2026-10-21 Kenの追加回答）。

### class・列幅等の案

- 検索は`.search-box`・`.detail-toggle`・`.search-panel`を共用し、顧客固有は`.last-purchase-field`。入力は`customer-keyword`・`customer-purchased-from`・`customer-purchased-to`、日付エラーは`customer-date-error`
- 一覧は`.customers-scroll`・`.customers-table`。列は`.customer-name`・`.customer-email`・`.customer-count`・`.customer-amount`・`.customer-purchased`・`.customer-detail`
- 詳細リンクは40px角の`.detail-link`。公式[Lucide eye SVG](https://github.com/lucide-icons/lucide/blob/main/icons/eye.svg)を使い、仮の`customer-detail.php`へ進む。URL・パラメータにメールアドレスを入れない。顧客IDと本番URLは未確定
- 表は`table-layout: fixed`・最小幅`68rem`の調整案。固定列は氏名`14.4rem`・購入回数`8.4rem`・金額`14rem`・最終購入日`11.2rem`・詳細`6.6rem`。メール列だけ残り幅を使い、834pxを境にした幅の切り替えを削除。氏名は全角6文字程度以上が入る幅を確保し、詳細列は40pxの丸＋左右12px＋罫線を収める
- `.customer-email-value`のtitleに全文を持ち、エスケープした`@`前後の各部分を`.email-part`に入れて間に`wbr`を置く。各部分は改行せず、列に収まらない部分だけ省略する。Bladeでも同じエスケープ・分割・`wbr`の処理が必要なことをPHPにコメントした
- 金額見出しの`.tax-note`は改行しないまとまりとし、「込）」だけが別行へ落ちないようにする
- 購入回数・購入金額・最終購入日は右揃え・`tabular-nums`。金額は`¥`＋3桁区切り、最終購入日は日付だけの`time[datetime]`
- 表示例は架空の6件で、長い氏名・長い`example.com`メール・購入1回・7桁の金額・実在しない000始まりの電話番号を含む。986件・1ページ50件・全20ページ、最終購入日の新しい順は制作上の表示例
- `customer-detail.php`は未作成。URL・顧客ID、集計に含める注文、購入回数の単位、キャンセル・返品時の最新情報などは未確定のまま、制作PHPに業務処理を持たせない

### 制作2回目の確認結果

- `npm run sass`、DDEVの`php -l`、`git diff --check`を確認した
- Chrome・WebKitで1280×800・1024×768・920×800・834×1194の通常と全5preview、各ブラウザ24条件を確認。横はみ出し・コンソールエラー・通信エラーはない。Safariアプリ自体での操作確認とは区別する
- 氏名の内容幅は全角約7.5〜10文字分。メールは`@`前後の各部分が1行に収まり、途中改行はない。920px・834pxの最長メールだけ「…」となり、title・テキストには全文を維持する
- 詳細アイコンは40px角でセルの左右余白内に収まり、読み上げ名・titleが氏名と一致する。金額見出しの「（税込）」は一まとまりのまま2行目へ移る
- 全状態で氏名リンク・電話番号列はない。通常・途中のページ・日付エラーでは6列、購入者なし・検索結果0件・取得失敗では表なし。日付エラーの2欄・詳細検索の開閉・条件クリア・現在地・詳細リンクの3pxフォーカス枠も確認した
- 存在しない`favicon.ico`へのブラウザの自動アクセスで発生した404は、顧客一覧のheadに空のfaviconを指定して防ぐ。共通部品には変更を加えていない
