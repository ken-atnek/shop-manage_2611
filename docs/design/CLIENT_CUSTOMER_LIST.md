# Client 顧客一覧 — 構成・項目の検討

## 位置づけ

2026-10-21のKenの決定を基に、Clientの顧客一覧を整理する画面資料。状態は「仕様検討中」。今回は資料だけを作成し、PHP・HTML・Sass・CSS・JSは作成しない。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。見た目や未指定の検索条件を推測で確定しない。

顧客の定義・メールアドレスによる集約・閲覧範囲・集計条件は[SPECの顧客管理の確定事項](../SPEC.md#顧客管理の確定事項)を正とし、本資料には業務仕様を重複して定義しない。詳細画面は[顧客詳細](CLIENT_CUSTOMER_DETAIL.md)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、共通構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)を参照する。バックエンドへの確認は[QA No.11](../QA_BACKEND.md#no11-顧客管理のデータ閲覧範囲会員との関係)にまとめる。

## 確定している前提（2026-10-21）

- 対象はClient。顧客情報は閲覧のみで、編集操作を置かない
- サイドバーの「顧客管理」から本一覧へ入り、一覧と詳細の2画面で構成する
- 一覧は、Clientが閲覧できる購入者を1人につき1行で表示する。集約条件と閲覧範囲はSPECを参照する
- 氏名・電話番号などに使う「最新の注文」は、そのClientが閲覧できる注文（所属パートナーの店舗の注文）のうち最新のものとする
- 購入回数・購入金額の合計・最終購入日も同じ範囲の注文だけで算出し、ほかのパートナーの注文は表示にも集計にも使わない
- 検索は氏名・メールアドレス・電話番号のキーワードと、最終購入日の期間を使う
- 検索・日付入力は受注一覧・商品一覧の共通部品を利用する
- CSV書き出しは最初は置かない

## 項目

### 一覧の列（確定した構成・表示）

| 列 | 内容・表示 | 参照・補足 |
|---|---|---|
| 氏名 | Clientが閲覧できる注文のうち、最新の注文で確定した注文者の氏名 | 注文者情報の項目詳細は未確定 |
| メールアドレス | 注文者のメールアドレス | 顧客をまとめる条件はSPECを参照 |
| 電話番号 | Clientが閲覧できる注文のうち、最新の注文で確定した注文者の電話番号 | 届け先の電話番号ではない |
| 購入回数 | Clientが閲覧できる範囲の注文を対象にした回数 | キャンセル・返品と数え方の単位は未確定 |
| 購入金額の合計（税込） | Clientが閲覧できる範囲の注文の合計金額を税込で表示 | キャンセル・返品を含めるかは未確定 |
| 最終購入日 | Clientが閲覧できる範囲で対象の顧客が最後に購入した日 | 表示形式は画面制作時に調整 |

### 検索項目

| 項目 | 対象・入力 | 区分 |
|---|---|---|
| キーワード | 氏名・メールアドレス・電話番号 | 対象は確定。一致方法は未確定 |
| 最終購入日 | 開始日・終了日の期間 | 対象は確定。境界・片側指定等の細則は未確定 |

| 対象 | 案・確認内容 |

| 空・0件・失敗 | 購入者なしと検索結果0件は既存一覧の状態部品で文言を分ける。取得失敗は店舗一覧の`.list-error`を参考にする |

新しい色・余白・寸法のトークンはこの資料では確定しない。

## 未確定事項

- 購入回数・購入金額の合計にキャンセル・返品の注文を含めるか。[SPECの未確定事項](../SPEC.md#顧客管理の未確定事項)で集計と合わせて決める
- 購入回数を、店舗ごとに分かれた注文の数で数えるか、購入の単位で数えるか。1回の購入で同じパートナーの複数店舗から買う場合を含めて決める
- 最新の注文がキャンセル・返品だった場合に、その注文者情報を氏名・電話番号などの基本情報に使うか
- 会員アカウントとの関係、メールアドレス変更時の扱い、注文者情報の項目詳細はSPECを参照する
- 店舗での絞り込みを一覧へ置くか
- 顧客詳細のURLやパラメータにはメールアドレスを出さない。顧客テーブルのIDなどの識別方法と、詳細へのリンク位置を決める
- キーワードの一致方法、最終購入日期間の境界・片側指定・タイムゾーン
- 1ページの件数と、1ページだけの場合のページ送り表示
