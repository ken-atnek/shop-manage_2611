# Client 商品一覧 — 構成・項目の検討

## 位置づけ

2026-10-19のKenの決定を基に、Client商品一覧の構成・項目・操作・状態を整理する画面資料。

「確定」は今回の決定と再利用する共通仕様、「案」はKenが画面で調整する内容、「未確定」は業務条件など今後の確認事項とする。2026-10-19に制作用PHP・Sass・生成CSSを作成し、同日のKenの決定で公開バッジと在庫・日時の2行表示を反映した。JSは既存の共通JSだけを使用する。実装値・確認結果は末尾の実装メモへ分け、残りの見た目は引き続き調整する。

業務仕様は[仕様書](../SPEC.md)、共通の見た目は[デザイントークン](../../DESIGN_TOKENS.md)、共通部品の参照元は[Client受注一覧資料](CLIENT_ORDER_LIST.md)、実装ルールは[実装連携ガイド](../coding/IMPLEMENTATION_REFERENCE.md)を参照する。制作時はCodexが作成し、Kenが調整、Claudeが確認する。

2026-10-20追記：商品詳細と商品登録は同じフォームとし、一覧の編集アイコンからその編集状態へ入る。公開状態はフォーム内のラジオで選び、保存時に反映する。詳細・案・未確定事項は[Client商品詳細（登録・編集）資料](CLIENT_PRODUCT_FORM.md)を参照。在庫管理なしの用途・操作・表示は同日のKenの決定で確定。用途・操作・表示の経緯は同日の記録として残す。2026-10-21、Ken承認済みの[QA No.12](../QA_BACKEND.md#no12-商品一覧のblade化で確認したいこと)・[No.13](../QA_BACKEND.md#no13-商品一覧の絞り込みの細則)により、在庫欄のマークアップ・日付の形式エラー文・検索細則・照合順序の挙動を確定し、本資料と申し送りへ反映した。制作用PHPには在庫管理なしの表示例を1行追加した。

## 確定している前提（2026-10-19／2026-10-20・2026-10-21追記）

- 対象はClientの商品一覧。商品の確認・検索・絞り込みと、商品詳細への編集導線を設ける
- 規格（サイズ・色など）はいったん扱わず、商品コードも設けない。IDはシステムのIDとする
- 一覧は`table`で1商品1行。`thead`内の列見出しは`th scope="col"`とする
- KPIは置かない。KPIは受注一覧だけで使用する
- 公開／非公開の切り替えは安全のため商品詳細で行う。一覧は状態の表示だけとする。詳細フォームではラジオ「公開／非公開」を使い、保存と同時に反映する（2026-10-20）
- 入稿の有無は一覧に出さず、商品詳細のチェックボックス「入稿あり」で設定・確認する。ありの場合の必須／任意・注文者向け説明文欄は案・未確定（2026-10-20）
- 「在庫を管理しない」は在庫数を持たずにいつでも販売できる商品（受注生産・名入れなど）向けの設定。フォームではチェック時に在庫数欄を無効化する（JSは2回目）。一覧では`<span aria-hidden="true">—</span><span class="sr-only">在庫管理なし</span>`を表示し、「在庫切れ」「残りわずか」のラベルは付けない。検索では「在庫あり」に含め、ほかの2区分には含めない（2026-10-21、QA No.12・No.13）
- 対応対象は既存方針と同じPC・タブレット。スマートフォン対応は今回の対象に含めない
- 受注一覧から共通化した`common.scss`・`common.js`と、既存のボタンmixinを再利用する

## 画面構成と共通部品（確定）

ヘッダー・サイドバーは既存のClient共通レイアウトを使う。メイン領域はページ見出し → 検索・詳細検索 → 一覧見出し → 商品テーブル（または空状態）→ ページ送りの順とする。

ページ見出しは「商品一覧」だけとし、受注一覧のような日付は出さない（Kenの決定、2026-10-19）。

スクロールは縦横ともページ全体で行い、商品テーブルの中にはスクロールを出さない（Kenの決定、2026-10-19）。`.products-scroll`は通常のラッパーとして残し、スクロール用の`role`・`aria-label`・`tabindex`は付けない。表が画面より広い場合はレイアウト全体を広げ、ヘッダーの面・下線とサイドバーの面をページの右端・下端までつなぐ。

`table`には、一覧見出しの`h2`のidを`aria-labelledby`で参照して名前を付ける。

| 領域 | 使用する共通部品 | 商品一覧での内容 |
|---|---|---|
| ページ見出し | `.page-heading` | 主見出し「商品一覧」だけ。日付は出さない |
| キーワード・詳細検索 | `.search-box`・`.filter-bar`・`.detail-toggle`・`.search-panel` | 商品名・IDの検索と詳細条件 |
| フォーム | `.form-field`・`.form-check`・`.check-group`・`.date-range` | 公開状態・在庫の状態・更新日の期間 |
| 一覧見出し | `.list-heading` | 商品一覧の対象件数を表示 |
| 空状態 | `.list-empty`・`.show-all` | データなし、検索結果0件、全件表示への導線 |
| ページ送り | `.pagination` | 受注一覧と同じ表示ルール・見た目 |
| ボタン | `button-base`・`button-primary`・`button-secondary` | 検索は主、条件クリアは副。詳細検索は既存の切り替えボタン |

詳細検索の内部構造は既存の`.search-panel-inner`・`.search-fields`・`.search-actions`も再利用する。受注一覧固有のKPIや検索項目の全幅指定は、そのまま商品一覧の仕様として持ち込まない。商品一覧のフォーム配置は制作時に確認する。

## 検索（確定）

| 場所 | 条件 | 入力方法・文言 |
|---|---|---|
| キーワード | 商品名・ID | プレースホルダー「商品名・IDで検索」 |
| 詳細検索 | 公開状態 | チェックボックス「公開」「非公開」 |
| 詳細検索 | 在庫の状態 | チェックボックス「在庫あり」「残りわずか」「在庫切れ」 |
| 詳細検索 | 更新日 | 開始日・終了日の期間入力。`.date-range`を使用 |

### 詳細検索の共通動作

- キーワード欄に「検索」、その隣に「詳細検索」を置く。パネル内の操作は「条件をクリア」「この条件で検索」
- 開閉・パネル内クリアには`common.js`を使用する。`.detail-toggle`の`aria-controls`でパネルのidを参照し、`aria-expanded`とパネルの`inert`を同期する
- 通常の初期表示ではパネルを閉じ、開閉時のフォーカスは詳細検索ボタンに残す。入力エラー時は対象欄が見えるようパネルを開く
- 「条件をクリア」はパネル内の入力値を空にし、チェックを解除する。キーワードは維持し、パネル内の最初の`input`へフォーカスする。クリアだけで検索実行・全件表示への切り替えは行わない
- 受注一覧では最初の入力が注文日の開始日だが、商品一覧では実際のDOM順に従う。更新日の開始日へ固定するために共通JSを変更しない
- チェックボックス群と更新日の期間は`fieldset`・`legend`でまとめ、各入力に対応する`label`を付ける。キーワードもプレースホルダーだけをラベルの代用にしない

### 検索の細則（2026-10-21、QA No.13で確定）

業務仕様の正は[SPECのClient商品一覧の確定事項](../SPEC.md#client商品一覧の確定事項)。表示例のPHPでは検索・判定を実装せず、バックエンドで以下の条件を適用する。

- キーワードは前後の空白を除き、商品名は部分一致、IDは入力が半角数字だけのとき完全一致とする。商品名とIDはORで検索する
- 商品名の部分一致はDBの照合順序`utf8mb4_unicode_ci`に従い、英字の大文字・小文字、全角・半角、ひらがな・カタカナ、濁点・半濁点の有無、小さい文字を区別しない。「マグ」で「まぐ」、「ハン」で「パン」も一致する。取りこぼしを避けるため、この挙動を維持する（QA No.13の追記）
- 同じ条件のチェックが全部未選択の場合は、その条件を使わない。同じ条件内の複数選択はOR、キーワード・公開状態・在庫の状態・更新日の間はANDとする
- 在庫の状態は互いに重ならない区分とし、在庫を管理する商品は在庫切れ＝0、残りわずか＝1〜5、在庫あり＝6以上とする。「残りわずか」の基準値5は全商品共通で、一覧のラベル表示と検索の両方に使う
- 在庫管理なしの商品は、検索では「在庫あり」に含め、「残りわずか」「在庫切れ」には含めない。一覧の在庫数欄は「—」のままとする
- 更新日は片側指定可。開始日だけはその日以降、終了日だけはその日までとし、開始日・終了日の両日を含む。日付の判定は日本時間（`Asia/Tokyo`）で行う
- 更新日時の表示は日本時間とする

## 並び順・ページ送り（確定）

- 更新が新しい順で固定し、並び替えの操作は置かない。同じ更新日時の順序は未確定で、仮にID降順とする
- 1ページ50件。`.pagination`を使い、受注一覧と同じ部品・表示ルールとする
- ページ番号と省略記号は最大7項目。全7ページ以下は全番号を表示。8ページ以上は最初・最後・現在ページの前後1ページを基本とし、空く範囲を「…」で示す
- 先頭付近は`1 2 3 4 5 … 最終`、途中は`1 … 前 現在 次 … 最終`、末尾付近は`1 … 最終-4 最終-3 最終-2 最終-1 最終`
- 「前へ」は2ページ目以降、「次へ」は最終ページより前だけ表示する。現在ページは`aria-current="page"`で示す。省略記号とページ位置表示は操作対象にしない
- 配置・現在ページ・ホバー・フォーカス・前後のアイコンは共通部品のままとする。ページ数・現在ページ・URLと検索条件の引き継ぎはバックエンドで組み込む

## 操作と状態（確定）

### 画面全体の状態

| 状態 | 表示・操作 | 制作確認用URL |
|---|---|---|
| 通常 | 商品テーブルとページ送り | `products.php` |
| 途中のページ | 共通ページ送りの中間部分を確認 | `products.php?preview=pager-middle` |
| データなし | 「まだ商品はありません」 | `products.php?preview=empty` |
| 検索結果0件 | 「条件に一致する商品はありません」＋「すべての商品を表示」「条件をクリア」 | `products.php?preview=no-results` |
| 更新日の入力エラー | 開始日と終了日が逆転した例。パネルを開き、両方の入力と共通のエラー文を関連付ける | `products.php?preview=date-error` |

データなし・検索結果0件は受注一覧と同じ`.list-empty`を使用し、テーブルとページ送りを案内箱に置き換える。「すべての商品を表示」には`.show-all`を使う。

検索結果0件の「条件をクリア」は、詳細検索パネル内のクリアと区別する。受注一覧と同様に解除の導線を用意するが、遷移先や解除対象・再検索の扱いはバックエンド組み込み時に確認する。`common.js`のパネル内クリアだけで検索結果まで変わるとは扱わない。

`preview`は受注一覧と同じ名前を使用する制作確認専用の仕組み。Laravel・Bladeへ移植する業務パラメータではない。

### 更新日の入力エラー

- 共通の`$color-error`（`#D21F3C`）による入力枠と`.form-error`のエラー文を使う
- 開始日・終了日の両方に`aria-invalid="true"`を付け、`aria-describedby`でfieldset内の1つのエラー文を参照する。正常時はエラー用属性・文を出さない
- 形式が正しくない場合は「日付を正しく入力してください」、開始日・終了日の逆転は「終了日は開始日以降の日付を指定してください」（QA No.12で確定）。制作確認用の`date-error`は逆転の例のままとし、形式エラーの表示例は追加しない。日付の判定はバックエンドで行う

### 一覧内の表示状態

| 状態 | 確定している表示 |
|---|---|
| 画像なし | 画像の位置に代わりの表示を置き、画像がないことが文字でも伝わるようにする。具体的な見た目は未確定 |
| 在庫切れ | 在庫数0に「在庫切れ」の文字ラベルを添える |
| 残りわずか | 在庫数1〜5に「残りわずか」の文字ラベルを添える。基準値5は全商品共通 |
| 在庫あり | 在庫数6以上はラベルなし。在庫管理なしも検索ではこの区分に含める |
| 在庫管理なし | 在庫数欄は「—」と読み上げ用「在庫管理なし」。在庫切れ・残りわずかのラベルなし |
| 非公開 | 公開状態に「非公開」。行全体の文字や画像を薄くしない |

公開状態と在庫の状態は別の情報として表示する。画像なしや非公開でも、商品名・価格・在庫数・編集導線の読み取りや操作を妨げない。

### classと共通部品

### 決定済みの見た目と調整中の寸法

- 表の最小幅は`86rem（860px）`へ縮小（旧960px）。在庫列は`9rem`、更新日時列は`11rem`、バッジを収める公開状態列は`10rem`。商品名だけを残り幅（最小幅時264px）にし、固定レイアウトで長文を行数制限なしに折り返す。セル余白は`1.2rem`のまま。列幅・最小幅は今回の実測による調整値
- 公開状態は角の丸い塗りのバッジ。公開は`$color-publish-public（#3A5F95）`、非公開は`$color-publish-private（#6B7079）`に`opacity: 0.7`。白文字・`fz(14)`・500（太字ではない）、幅`5em`・中央ぞろえ、高さ`2.8rem`、左右余白`1.2rem`、角丸`100vmax`、枠なし。非公開の実表示約2.8:1は、控えめに見せるためのKenの決定として白文字4.5:1の例外（2026-10-19）。ホバー色は変えずカーソルは`default`。非公開の行全体は薄くしない
- 在庫ラベルは数字の下に`display: block`で置き、`fz(12)`の補助色文字・右揃えを維持。左余白をなくし、全行の数字の右端をそろえた。「3・残りわずか」は2026-10-21に確定した基準値5の範囲内の表示例
- 更新日時は1つの`time`の中を日付・時刻の2つの`span`に分け、block表示・右揃え・`tabular-nums`。文字サイズは変えず、子も`font-size: inherit`。`datetime`は元の値を維持
- 画像なしは48px角のグレーの面＋「画像なし」。`image-off`案は採用していない
- 行ホバーは`$color-bg-detail`。編集リンクは40px角・丸い領域で、補助色→本文色＋白背景のホバー。通常は1pxの透明枠、ホバーでは`$color-border-card`の1px枠を表示し、文字色・背景色・枠色に`$transition-base`のtransitionを付ける
- ページ固有の指定はすべて`products.scss`内。`fz()`を入れ子で重ねず、table内部の構造要素・time等は`font-size: inherit`。入力欄の16px固定は共通スタイルを使用
