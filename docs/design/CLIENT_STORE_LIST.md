# Client 店舗一覧 — 構成・項目の検討

## 位置づけ

2026-10-20のKenの決定を基に、Clientの店舗一覧を整理する画面資料。状態は「制作中」。一覧の制作は完了し、Kenの見た目調整・確認とフォーム制作を残す。今回決まった内容と、引き続き残る案・未確定事項を分けて記載する。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。見た目や入力条件を推測で確定しない。

店舗と送料の業務仕様は[SPECの店舗と送料の確定事項](../SPEC.md#店舗と送料の確定事項)を正とし、本資料には再掲しない。フォームは[店舗の登録・編集](CLIENT_STORE_FORM.md)、共通一覧は[商品一覧](CLIENT_PRODUCT_LIST.md)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、共通構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)・[Client共通申し送り](../coding/HANDOFF_CLIENT_COMMON.md)を参照する。

## 確定している前提（2026-10-20）

- 対象はClient。呼び方は「店舗」とするが、今後変更する可能性はある
- 画面は一覧と、登録・編集を共用する1フォームの2つ
- サイドバーは「店舗」1項目だけとし、一覧へ入る
- 一覧に「店舗を追加」ボタンを置き、新規フォームへ進む。商品一覧の登録導線とは異なる
- 一覧のデータは[SPECの一覧の並び順・集計・更新日時](../SPEC.md#一覧の並び順集計更新日時)に従う。並び順・商品数の集計条件・更新日時の契機は画面側で別に定義しない
- 送料方式の表示は「サイズ別」／「サイズ共通」とする
- 送料は店舗の登録・編集フォームで設定する
- 商品フォームの表示文言は「店舗」へ変更済み（2026-10-20）。サイドバーも「店舗」へ変更済み（2026-10-20）。コードの名前は変更しない

## 項目

### 一覧の列（確定した構成・表示）

| 列 | 内容・表示 | 参照・補足 |
|---|---|---|
| ID | 店舗IDを商品一覧と同じ数字の書き方で右揃えに表示。表示例は1・2・3 | 先頭への追加は2026-10-20、Kenの決定 |
| 店舗名 | 登録した店舗名をテキスト表示。長い名前は折り返す | 購入画面にも表示するかは未確定 |
| 運送会社 | 選択済みの会社名を表示 | 初期対象・規格は[SPEC](../SPEC.md#運送会社の規格正の資料)を参照 |
| 送料 | 「サイズ別」／「サイズ共通」の文字で表示（確定） | 都道府県欄への入力補助「全国一律」と区別する |
| 商品数 | 集計済みの商品数を右揃えで表示 | 集計対象は[SPEC](../SPEC.md#一覧の並び順集計更新日時)で確定 |
| 更新日時 | 日付・時刻を商品一覧と同じ2行で表示 | 更新の契機は[SPEC](../SPEC.md#一覧の並び順集計更新日時)で確定 |
| 編集 | 商品一覧と同じ編集アイコンから編集フォームへ遷移 | 読み上げ名・titleには対象の店舗名を含める |

ID列を追加した理由は、商品一覧と揃えること、登録順の根拠が見えること、やり取りで店舗を特定できること（2026-10-20、Kenの決定）。ID列は商品一覧と同じ`product-id`クラス・幅6.4rem・右揃え・`tabular-nums`・折り返しなしとする。

送料の方式と、都道府県欄への一括入力補助「全国一律」は別の概念。[SPEC](../SPEC.md#店舗と送料の確定事項)の送料方式を増やすものではない。

## 操作と状態

| 操作・状態 | 表示・動作 | 区分 |
|---|---|---|
| 店舗を追加 | `store-form.php`へ進む | 確定。フォームは次段階で制作するため現在はリンク切れ |
| 編集 | `store-form.php?id={ID}`へ進む | 確定。フォームは次段階で制作するため現在はリンク切れ |
| 通常 | SPECで決めた順序のまま店舗を一覧表示する | 順序は確定。表示の細部は案 |
| 店舗未登録 | 「店舗がまだ登録されていません」と「店舗を追加」への導線を表示 | 確定。共通の`.list-empty`・`.empty-actions`を利用 |
| 取得失敗 | 「店舗一覧を取得できませんでした」・補助文・「再読み込み」を表示。0件とは区別し、表は出さない | 表示案。既存一覧に取得失敗部品がないため、`.list-empty`に店舗用の`.list-error`を追加。`role="alert"`を付ける |
| 並び替え・ページ送り | 操作・ページ番号・次へ／前へは表示しない | 確定 |
| 削除・停止 | 最初は操作を置かない | 案。停止時等の商品の扱いは未確定 |

検索を置かないため、検索結果0件や詳細検索の開閉状態は制作候補に含めない。リンクは`a`、操作ボタンは`button`を使い、今回は行全体をクリック対象にせず、編集リンクだけを操作対象にする。

## 見た目の案（Kenが画面で調整・決定）

| 対象 | 案・確認内容 |
|---|---|
| 共通部分 | 商品一覧のヘッダー・サイドバー・見出し・罫線・表の文字を基準にする |
| 追加ボタン | 既存`button-base`＋`button-primary`、Lucideの`plus`。見出しと左右に配置し、`max-width: $tb`（834px）以下は下段の左寄せ。共通見出しの間隔1.6rem／2.4remを使用 |
| 一覧 | `table-layout: fixed`。ID6.4rem（商品一覧に合わせる指定）・運送会社12rem・送料11rem・商品数8rem・更新日時11rem・編集6.4rem、店舗名は残りの幅。セル余白1.2rem。商品一覧の罫線・文字・ホバーを転記 |
| PC／タブレット | 1280×800・834×1194で横はみ出しを作らない。表の最小幅は設定せず、店舗名は省略・行数制限なしで折り返す（`overflow-wrap: anywhere`）。送料方式は1行、日時は2行。ページ全体で縦スクロールする |
| 状態 | 方式は文字で伝える。公開／非公開のバッジを店舗の状態として流用しない |
| 空・エラー | 共通の空状態の箱を利用。空状態にも主ボタンで追加導線を置く。エラーは既存のエラー色で文言を強調し、通常URLへの再読み込みリンクを置く |

新しい色・余白・寸法のトークンはこの資料では確定しない。

### 制作ファイル・確認URL（2026-10-20）

- 編集元：[stores.php](../../shop-partner/stores.php)
- 固有Sass：[stores.scss](../../shop-partner/assets/scss/stores.scss) → [stores.css](../../shop-partner/assets/css/stores.css)。`common.css`の後に読み込む
- 通常：`https://shop-manage-2611.ddev.site/shop-partner/stores.php`
- 未登録：通常URLに`?preview=empty`。取得失敗：`?preview=error`
- 3店舗・商品数・日時・previewの分岐は制作確認専用。Bladeへ移さず、バックエンドの実データ・状態分岐へ置き換える
- `$currentPage = 'stores'`で共通サイドバー「店舗」に`aria-current="page"`を付ける。アイコンはLucideの`store`
- 店舗専用JSは作成せず、共通の`common.js`だけを読み込む。headのサイドバー初期化は商品一覧と同じ
- `scripts/export-html.php`へ追加済み。書き出しでは通常状態のみを出力し、共通ナビ・新規／編集リンクを`.html`へ切り替える。フォーム未作成によるリンク切れは今回の了承範囲
- 表の基本スタイル・ID列（`product-id`）・日時2行・数値の桁揃え・編集リンクを`products.scss`から転記。今後の共通化候補とし、今回は`common.scss`を変更しない

各段階の依頼を受けて制作・確認し、最後に引き渡し内容を整理する。
