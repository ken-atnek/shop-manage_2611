# Client 集計 — 構成・項目の検討

## 位置づけ

2026-10-22のKenの決定を基に、Client集計の構成・項目・操作・状態を整理する画面資料。業務仕様の正は[SPECの集計の確定事項](../SPEC.md#集計の確定事項)とし、本資料には画面制作に必要な前提だけをまとめる。

「確定」はSPECの決定事項、「案」はKenが画面で調整・決定する内容、「未確定」は今後の確認事項とする。画面の構成・見た目は案であり、制作は未着手。本資料ではPHP・Sass・JSを作成しない。

名前は画面資料`CLIENT_SALES.md`、制作用PHP`shop-partner/sales.php`、固有Sass`shop-partner/assets/scss/sales.scss`を候補とする案。見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、共通構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)、実装時の書き方は[実装連携ガイド](../coding/IMPLEMENTATION_REFERENCE.md)を参照する。

## 確定している前提（2026-10-22）

以下は[SPECの集計の確定事項](../SPEC.md#集計の確定事項)の要約。集計条件の詳細はSPECを参照する。

- 対象はClient。「何が・いつ・どれだけ売れたか」を受注日で集計する
- 初期期間は今月。前月／翌月のボタンと月のセレクト、別に期間指定欄を置く。今月では翌月へ進めず、月のセレクトは最初の注文月から今月まで。期間指定は両日を含み、日本時間で判定する
- 表の上に売上の合計（税込・商品代のみで送料を含めない）・販売個数の合計・注文件数を表示する。注文件数は店舗ごとの注文数
- 商品ごとの表は全商品が対象で、上位N件に限定せずページ送りを付ける。列は商品名・購入回数・販売個数・売上（税込・商品代のみ）
- 商品ごとの購入回数はその商品を含む注文数。商品IDでまとめ、期間内の最新の注文時の商品名を表示する。初期は売上の多い順で、販売個数の多い順に切り替えられる
- 発送状況が「キャンセル」「返品対応」の注文は各数値に含めず、それぞれの件数も出さない。後日の変更で過去の数字が変わることがある
- 店舗のセレクトは「すべての店舗」が初期値。店舗が1つのパートナーでは表示しない
- CSVは選択中の期間・店舗の合計と商品ごとの表を出力し、個人情報を含めない
- 金額は税込で、見出し・列名に「（税込）」を付ける。送料合計・税抜・税率別内訳・売上推移のグラフや表・客単価は置かない

## 画面構成（案）

ヘッダー・サイドバーはClient共通レイアウトを使う案。メイン領域は下表の順に並べる案とし、配置・間隔はKenが画面で調整する。

| 順 | 領域 | 内容の案 | 再利用・参照する画面や部品 |
|---|---|---|---|
| 1 | ページ見出し | `h1`に「集計」だけを表示する案 | 商品一覧の`.page-heading` |
| 2 | 期間の操作 | 前月ボタン・月のセレクト・翌月ボタンを1行に並べ、その下に開始日・終了日・「適用」を置く案。期間指定欄の開閉／常時表示は下記で比較 | 受注一覧・商品一覧の検索枠、日付入力`.date-range`、共通フォーム・ボタン |
| 3 | 店舗・CSV | 店舗のセレクトと文字ボタン「CSVをダウンロード」を同じ行に置く案。単一店舗ではセレクトを出さない。CSVの位置は未確定 | 既存の共通セレクト、`.filter-bar`の配置、ボタンmixin |
| 4 | 合計3つ | 左から売上の合計（税込）・販売個数の合計・注文件数を等幅で並べる案。表示専用とし、クリックで絞り込まない | [受注一覧のKPI](CLIENT_ORDER_LIST.md#現在のデザイン方向c案v91以降の資料更新を含む)の白い面・細い枠・数値の強弱を参考にする |
| 5 | 商品ごとの表 | 商品名・購入回数・販売個数・売上（税込）の4列。数値は右揃え・`tabular-nums`にする案。並び替えUIは下記で比較 | [商品一覧の表](CLIENT_PRODUCT_LIST.md#一覧の列確定)の見出し・罫線・商品名・数値の扱い |
| 6 | ページ送り | 商品表の下に既存部品を置く案。1ページ50件とするかは未確定 | [共通申し送りのページ送り](../coding/HANDOFF_CLIENT_COMMON.md#7-ページ送り)の`.pagination` |

## 項目

表示する値はSPECの確定事項。単位・書式・揃えは以下の案とし、商品一覧と受注一覧の読みやすさに合わせてKenが調整する。例の数字は書式の説明用。

### 合計3つ

| 項目 | 表示する値 | 単位・書式の案 | 揃えの案 |
|---|---|---|---|
| 売上の合計（税込） | 選択中の期間・店舗の商品代の合計。送料を含めない | `¥1,234,567`。既存一覧と同じ`¥`＋3桁区切りで「円」は重ねない。0は`¥0` | ラベルは左、数値は右揃え・`tabular-nums` |
| 販売個数の合計 | 同じ条件の販売個数の合計 | `1,234個`。3桁区切り＋「個」。0は`0個` | 同上 |
| 注文件数 | 同じ条件の店舗ごとの注文数 | `1,234件`。3桁区切り＋「件」。0は`0件` | 同上 |

3つは表の現在ページだけの小計ではなく、選択中の期間・店舗全体の合計を表示する。単位は数値に続け、数値と単位が離れて折り返さない案。

### 商品ごとの表

| 列 | 表示する値 | 単位・書式の案 | 揃えの案 |
|---|---|---|---|
| 商品名 | 商品IDでまとめた、期間内の最新の注文時の商品名 | 商品一覧と同じく長い名前は全文を折り返し、行数制限で省略しない案。画像・商品詳細へのリンクは未確定 | 左揃え |
| 購入回数 | その商品を含む注文数 | `1,234回`。3桁区切り＋「回」。販売個数と区別する案 | 右揃え・`tabular-nums` |
| 販売個数 | その商品の販売個数 | `1,234個`。3桁区切り＋「個」 | 同上 |
| 売上（税込） | その商品の売上。送料を含めない | `¥1,234,567`。`¥`＋3桁区切りで「円」は重ねない | 同上 |

列見出しの「（税込）」はまとまりとして扱い、必要な場合は「売上」と「（税込）」の2行にする案。商品名は現在の商品名へ置き換えず、SPECの注文時の商品名を表示する。

## 操作と状態

[SPECの操作と状態](../SPEC.md#操作と状態)に沿って整理する。業務上の条件は確定事項とし、表示・操作の細部は案を分ける。

| 操作・状態 | 確定している条件 | 表示・動作の案 |
|---|---|---|
| 初期表示 | 今月・すべての店舗・売上の多い順 | 1ページ目を表示する案。単一店舗では店舗セレクトを出さない |
| 月の切り替え | 前月／翌月ボタン・月のセレクトで切り替える。セレクトは最初の注文月〜今月 | 店舗・並び順を維持し、合計と表を更新して1ページ目へ戻す案 |
| 今月の翌月ボタン | 今月では押せない | ボタンを残して`disabled`にする案と、フォーカスを残す`aria-disabled="true"`にする案。後者は実行も抑止する。無効の表し方は未確定 |
| 最初の注文月の前月ボタン | 月セレクトの下限は最初の注文月 | 前月ボタンも残して無効にする案。`disabled`／`aria-disabled`の選択は翌月とそろえる案 |
| 期間の入力中・適用 | 開始日・終了日の両日を含み、日本時間（`Asia/Tokyo`）で判定 | 入力中は表示中の集計を維持し、「適用」で更新して1ページ目へ戻す案。月へ戻す操作や片側入力・未入力の扱いは未確定 |
| 期間指定中の月の操作 | 月指定とは別に期間指定欄を置く | 月の操作を無効にして「期間指定中」と示す案、または月の操作を残して操作時に月指定へ戻す案。どちらも実際の適用期間を明示する案 |
| 日付の逆転 | 商品一覧と共通の文言 | 「終了日は開始日以降の日付を指定してください」を表示。入力値を残し、開閉案ではパネルを開く案 |
| 日付の形式エラー | 商品一覧と共通の文言 | 「日付を正しく入力してください」を表示。入力値と適用前の条件を維持する案 |
| 店舗の切り替え | すべての店舗／選んだ店舗で絞り込む | 期間・並び順を維持し、合計と表を更新して1ページ目へ戻す案 |
| 並び順の切り替え | 売上の多い順／販売個数の多い順 | 期間・店舗を維持して1ページ目へ戻す案。合計は変えない。同じ値の商品の順序は未確定 |
| ページ送り | 全商品を対象にページ送りを付ける | 期間・店舗・並び順をリンク先へ引き継ぐ案。合計は期間・店舗全体のまま維持する |
| データなし | その期間・店舗に売上がない | 合計は`¥0`・`0個`・`0件`を表示し、表とページ送りの代わりに`.list-empty`で「この期間の売上はありません」を出す案。期間・店舗の操作は残す案 |
| 取得失敗 | 通信エラーとしてデータなしと区別する | 顧客一覧資料と同じく、共通部品はまだないため店舗一覧の`.list-error`を参考にする案。「集計を取得できませんでした」と再読み込みの導線を出し、未取得の合計を0と表示しない案 |
| CSVのダウンロード | 選択中の期間・店舗の合計と商品表を、個人情報なしで出力 | 適用済みの条件で実行する案。未適用の入力値は使わない。出力中の表示・重複操作の抑止・失敗時の案内の要否は未確定 |
| 読み込み中 | 取得方式は制作・組み込み時に確認 | 既存一覧と同じサーバー描画を前提に、独自の読込中表示は最初は置かない案。非同期取得が必要なら表示・通知を別途検討 |
| 権限不足・操作不可 | Clientの閲覧範囲はSPECに従う | 権限不足時の案内・遷移は共通方針に合わせて組み込み時に確認する案 |

集計は閲覧とCSV出力の画面。保存・編集・削除の操作は置かない案とし、保存前／保存中／保存完了や削除確認は対象外とする。日付の判定・集計・CSV生成はバックエンドで行い、制作用PHPには業務処理を作らない。

## 見た目の案（Kenが画面で調整・決定）

- 合計3つは受注一覧のKPIに近い白い面・1px枠・影なし・最小限の角丸にする案。ラベル500・強調する数値600を使い、選択枠・ホバー変化・指カーソルを付けず、表示専用とわかる見た目にする案
- 商品表は商品一覧の見出しの面・罫線・商品名の折り返し・数値の右揃え、ページ送りは既存の配置に合わせる案。長い商品名・大きな金額・多い件数で幅を調整する案
- 期間・店舗・CSVの間隔、合計の高さ、表の列幅は画面で調整する案。PC・タブレットを対象にし、834pxの縦向きでも確認する。表が収まらない場合は既存方針に合わせてページ全体でスクロールする案
- 文字は既存の流動フォント・`fz()`、色・罫線・ボタン・フォーカスは既存トークンと共通部品を使う案。新しいトークン・共通部品は作らず、必要になりそうなものは下記の未確定事項として残す

## 未確定事項

業務上の残りの論点は[SPECの集計の未確定事項](../SPEC.md#集計の未確定事項)を参照する。CSVの文字コード・ファイル名、発送状況の正式な呼称・選択肢と判定値、将来の月別推移、Masterの扱いは本資料で決めない。

画面側でKenが調整・決定する点：

- 期間指定欄を開閉するか、常に表示するか
- 期間指定中の月の操作の見え方と、月指定へ戻す操作。日付の片側入力・未入力時の扱い
- 並び替えを列見出しのボタンにするか、表の上のセレクトにするか。同じ売上・販売個数の商品が並ぶときの順序
- 1ページをほかの一覧と同じ50件にするか。1ページだけの場合にページ送りを出すか
- 商品の画像を表に出すか。商品名から商品詳細へリンクするか
- CSVボタンの位置。出力中の表示・操作抑止・失敗時の案内、売上がない場合のボタンの扱い
- 翌月・前月ボタンの無効の表し方（`disabled`／`aria-disabled`）。最初の注文月では前月も無効にするか、注文がまだない場合の月セレクトの表示
- 取得失敗の部品。現在は共通部品がないため、顧客一覧と同じく店舗一覧の`.list-error`を参考にする案
- 合計の単位・揃え・箱の寸法、表の列幅。表示専用の合計・並び替え表示を将来共通部品にする必要があるか（今回の新設はしない）

| 日付の逆転エラー | `?preview=date-error` | 期間指定欄を表示し、両入力と1つのエラー文を関連付ける |
| 取得失敗 | `?preview=error` | 顧客一覧と同じ名前。集計の取得失敗・再読み込みの案内 |
| 単一店舗 | `?preview=single-store` | 集計固有の候補。店舗セレクトを出さない |
| 期間指定中 | `?preview=date-range` | 集計固有の候補。任意期間の表示と月の操作との関係 |
| 最初の注文月 | `?preview=first-month` | 集計固有の候補。前月ボタンの下限の状態 |

日付の形式エラーも制作時の確認対象とし、専用previewを増やすかは画面制作時に検討する。`preview`は制作確認専用で、Laravel・Bladeへ移す業務パラメータにはしない。
