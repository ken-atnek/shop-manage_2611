# Client 顧客詳細 — 構成・項目の検討

## 位置づけ

2026-10-21のKenの決定を基に、Clientの顧客詳細を整理する画面資料。状態は「制作中」（2026-10-21、制作5回目）。顧客IDと基本情報（最新）、注文ごとの概要・商品明細・届け先・保存済みの備考とキャンセル／返品の記録を読み取り専用表示する。注文時点の注文者情報はDBに残すが履歴には表示せず、受注一覧への導線も置かない。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。購入時点の情報と最新情報を混同せず、未指定の項目やURLを推測で確定しない。

顧客の定義・メールアドレスによる集約・閲覧範囲・集計条件は[SPECの顧客管理の確定事項](../SPEC.md#顧客管理の確定事項)を正とし、本資料には業務仕様を重複して定義しない。一覧画面は[顧客一覧](CLIENT_CUSTOMER_LIST.md)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、共通構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)を参照する。バックエンドへの確認は[QA No.11](../QA_BACKEND.md#no11-顧客管理のデータ閲覧範囲会員との関係)にまとめる。

## 確定している前提（2026-10-21）

- 対象はClient。顧客情報は閲覧のみで、編集・保存操作を置かない
- 顧客一覧の末尾の「詳細」アイコンから対象の顧客詳細へ進む
- 電話番号は一覧の列には置かず、本詳細の基本情報で表示する。一覧のキーワード検索では電話番号を引き続き対象にする（2026-10-21 Kenの決定）
- 上部に顧客の基本情報として、そのClientが閲覧できる注文（所属パートナーの店舗の注文）のうち最新の注文で確定した注文者情報を表示する。「基本情報（最新）」の画面見出しと補助文は外すが、この参照元は変えない。氏名を箱のh2にし、メールアドレス・電話番号・郵便番号と住所はラベルなしで表示する
- 注文履歴・購入回数・購入金額の合計・最終購入日も同じ範囲の注文だけを対象とし、ほかのパートナーの注文は表示にも集計にも使わない
- 注文ごとに概要・商品明細・届け先を表示する。注文時点の注文者情報はDBに残すが、履歴には表示しない。基本情報（最新）の対象データは変えない
- 届け先は顧客をまとめる条件に使わず、注文ごとの情報として注文履歴内に表示する。その注文の注文者と同じ場合は「届け先：注文者と同じ」の1行だけ、違う場合だけ氏名・郵便番号と住所・電話番号の3行を表示する。判定方法はQA No.11の回答待ち
- 備考はある注文だけ、キャンセル／返品の記録は発送状況がキャンセル・返品対応で記録がある注文だけ表示する。入稿画像は表示しない
- 受注一覧へのリンク・ボタンは置かない
- 顧客IDは基本情報の箱内で、氏名の見出しの近くに読み取り専用で表示する。顧客テーブル方式と具体的なURLの形はバックエンド回答待ちで、画面のID表示と分けて扱う

## 項目

### 顧客ID

顧客IDは箱の外から中へ移し、氏名の見出しの下に「顧客ID 1042」のような小さい段落で表示する（`fz(14)`）。入力欄や`dl`にはしない。箱内の見出し近くに表示することは制作5回目で確定し、下側に置く位置はKenが画面で調整する案。画面へのID表示は確定だが、全パートナー共通の顧客テーブル方式はフロントの希望案でバックエンド回答待ち。詳細URLは顧客IDで作る方針を希望し、制作例の`customer-detail.php?id={顧客ID}`は仮の形とする。

### 基本情報（最新）

| 項目 | 内容・表示 | 区分 |
|---|---|---|
| 氏名 | Clientが閲覧できる注文のうち、最新の注文で確定した注文者の氏名。箱のh2に使う | 内容は従来どおり。見せ方は制作5回目で確定 |
| メールアドレス | 顧客をまとめている注文者のメールアドレス。連絡先の1段落目 | 内容は従来どおり。ラベルなし |
| 電話番号 | Clientが閲覧できる注文のうち、最新の注文で確定した注文者の電話番号。連絡先の2段落目 | 内容は従来どおり。ラベルなし |
| 住所 | Clientが閲覧できる注文のうち、最新の注文で確定した郵便番号・住所。「〒郵便番号 住所」を連絡先の3段落目に続ける | 内容は従来どおり。住所項目の採否は既存の案を維持し、今回は表示中のデータの見せ方だけ変更 |
| その他の注文者情報 | Clientが閲覧できる注文のうち、最新の注文で確定した情報 | フリガナ等の項目詳細は未確定 |

基本情報の連絡先は`dl`・`dt`・`dd`を使わず、3つのpで表示する。氏名と住所は省略せず折り返し、基本情報の文字サイズは従来どおり。メールアドレスも箱の幅を超える場合は折り返し、内容を欠落させない。購入状況の`dl`とラベルは残す。ページの「顧客詳細」と「顧客一覧へ戻る」は変更しない。

### 購入状況（表示・配置の案）

購入回数は「○回」、金額は一覧と同じ`¥`＋3桁区切り・税込、最終購入日は日付だけの`time`要素。ラベルの下の値はラベルと同じ左揃え・`tabular-nums`で表示する（制作2回目のKenの決定）。Clientが閲覧できる注文だけが集計対象となる点は確定しているが、キャンセル・返品を含めるか、購入回数を注文数と購入単位のどちらで数えるかは未確定。制作例の固定値で集計条件を確定しない。

### 注文履歴

| 項目・まとまり | 内容・表示 | 区分 |
|---|---|---|
| 注文の概要 | 注文番号・注文日時・店舗・合計金額（税込）・発送状況 | 日時・店舗・税込金額は制作3回目の構成で確定。注文番号・発送状況の表示と新しい順は既存の案 |
| 商品明細 | 商品名・個数・小計（税込）。商品名はリンクにしない | 制作3回目で確定 |
| 送料 | 明細の下に表示。0円は「送料（送料無料）」・¥0の例を置く | 表示は確定。0円時の文言は制作上の案 |
| 届け先 | 注文者と同じ場合は「届け先：注文者と同じ」の1行だけ。違う場合だけ氏名・郵便番号と住所・電話番号 | 制作4回目で確定。異なる場合はラベルなしの3行・`fz(14)` |
| お客様の備考 | ある注文だけ、受注一覧と同じ見出し「備考（お客様より）」で表示 | 制作4回目で確定。表示専用・`fz(14)` |
| キャンセル・返品の記録 | キャンセル・返品対応で記録がある注文だけ。見出しの下に注文単位の「理由・対応メモ」 | 制作4回目で確定。表示専用・`fz(14)` |
| 商品ごとのメモ | 記録を表示する注文の商品名の下に、保存済みの短いメモを表示 | 制作4回目で確定。`fz(14)`相当・補助色で区別 |
| 入稿画像 | 表示しない | 制作4回目で確定 |
| 注文時点の注文者情報 | DBには残すが、この画面の注文履歴には表示しない | 制作3回目で確定 |
| 受注一覧へのリンク | 置かない | 制作3回目で確定 |

1注文の順番は、概要（注文日時・店舗・合計金額（税込））→ 商品明細・送料 → 届け先 → 備考（お客様より）→ キャンセル・返品の記録とする。備考・記録がない場合は見出しや空欄も置かない。商品明細は受注一覧の明細テーブルと送料の見せ方を参考にし、表示専用の`table`で商品名・個数・小計（税込）を並べる。商品名は省略せず折り返す。概要に合計金額があるため、明細の下には合計を重複表示しない（制作3回目のKenの決定）。

届け先がその注文の注文者と同じ場合は「届け先：注文者と同じ」の1行だけを表示する。違う場合だけ、見出しの下を「氏名」「〒郵便番号 住所」「電話番号」の3段落で表示する。項目ラベル・`dl`・`address`は使わず、長い住所は2段落目の中で省略せず折り返す。見出しを含めて`fz(14)`とし、基本情報の箱の文字サイズは維持する。注文者情報の表示を外したため、以前の2列／1列の切り替えは廃止し、すべての幅で明細の下に届け先を置く。

判定済みの「注文者と同じ」かどうかの値はバックエンドから受け取る前提。購入時の「注文者と同じ住所に届ける」の選択を注文に記録する方法が望ましく、記録がない場合は注文時点の注文者情報と比較する。最新の基本情報は比較に使わない。具体的な保存方法・比較項目は[QA No.11](../QA_BACKEND.md#no11-顧客管理のデータ閲覧範囲会員との関係)の回答待ちで、制作PHPでは固定の表示例だけを使う。

備考・注文単位の理由／対応メモ・商品ごとのメモは、届け先と同じ`fz(14)`で表示し、改行を保持して長文を省略せず折り返す。商品メモは商品名の下に補助色で配置する。入力欄・保存操作・入稿画像は置かず、保存済みの注文内容を読むだけにする。

注文概要の合計金額はラベルの下に左揃えで表示し、`tabular-nums`を維持する。明細の個数・小計・送料は受注一覧と同じ右揃え・`tabular-nums`。受注一覧へのボタンと、そのURLに関する未確定事項は制作3回目で削除した。

## 未確定事項

- 購入回数・購入金額の合計にキャンセル・返品を含めるか。詳細での集計表示を追加する場合も[SPECの未確定事項](../SPEC.md#顧客管理の未確定事項)に従う
- 購入回数を、店舗ごとに分かれた注文の数で数えるか、購入の単位で数えるか。1回の購入で同じパートナーの複数店舗から買う場合を含めて決める
- 最新の注文がキャンセル・返品だった場合に、その注文者情報を基本情報に使うか
- 会員アカウントとの関係、メールアドレス変更時の扱い、注文者情報の項目詳細
- 店舗での絞り込みを詳細内に置くか。注文履歴へ店舗を表示する案とは分けて判断する
- 顧客詳細のURLやパラメータにはメールアドレスを出さない。顧客IDでURLを作る希望と、顧客テーブル方式は[SPECの未確定事項](../SPEC.md#顧客管理の未確定事項)・QA No.11の回答待ち。具体的なURLの形は未確定
- 一覧のキーワード検索に顧客IDを含めるか
- 注文履歴の表示単位を常時展開・折りたたみ・ページ送りのどれにするか。件数が多い場合の扱い
- 基本情報に住所を表示するか、購入状況を同じ箱の下部に置くか。現行の制作例では案として表示する
- 顧客の識別方法が決まった後の、未存在・権限外・取得失敗の判定とHTTP応答。見つからない状態の共通表示は現時点では画面の案
- 顧客単位の社内用メモを将来追加するか。今回は置かない
- 届け先が注文者と同じかの判定を、購入時の選択の保存で行うか、注文時点の情報比較で行うか。比較項目・表記ゆれの扱いを含めQA No.11の回答待ち
