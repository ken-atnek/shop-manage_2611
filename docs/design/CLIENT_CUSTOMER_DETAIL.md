# Client 顧客詳細 — 構成・項目の検討

## 位置づけ

2026-10-21のKenの決定を基に、Clientの顧客詳細を整理する画面資料。状態は「制作中」（2026-10-21、制作2回目完了）。基本情報と注文時点の履歴を読み取り専用表示し、履歴のラベルなし3行・文字サイズ・横並びの切り替え・数値の左揃え・受注一覧リンクのボタン表示を制作2回目の決定として反映した。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。購入時点の情報と最新情報を混同せず、未指定の項目やURLを推測で確定しない。

顧客の定義・メールアドレスによる集約・閲覧範囲・集計条件は[SPECの顧客管理の確定事項](../SPEC.md#顧客管理の確定事項)を正とし、本資料には業務仕様を重複して定義しない。一覧画面は[顧客一覧](CLIENT_CUSTOMER_LIST.md)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、共通構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)を参照する。バックエンドへの確認は[QA No.11](../QA_BACKEND.md#no11-顧客管理のデータ閲覧範囲会員との関係)にまとめる。

## 確定している前提（2026-10-21）

- 対象はClient。顧客情報は閲覧のみで、編集・保存操作を置かない
- 顧客一覧の末尾の「詳細」アイコンから対象の顧客詳細へ進む
- 電話番号は一覧の列には置かず、本詳細の基本情報と注文ごとの注文者情報で表示する。一覧のキーワード検索では電話番号を引き続き対象にする（2026-10-21 Kenの決定）
- 上部に顧客の基本情報として、そのClientが閲覧できる注文（所属パートナーの店舗の注文）のうち最新の注文で確定した注文者情報を表示する
- 注文履歴・購入回数・購入金額の合計・最終購入日も同じ範囲の注文だけを対象とし、ほかのパートナーの注文は表示にも集計にも使わない
- 注文ごとに、その購入時点の注文者情報と届け先を表示する。最新情報で過去の注文を上書きしない
- 届け先は顧客をまとめる条件に使わず、注文ごとの情報として注文履歴内に表示する
- 各注文から受注一覧へ進むリンクを置く

### 購入状況（表示・配置の案）

購入回数は「○回」、金額は一覧と同じ`¥`＋3桁区切り・税込、最終購入日は日付だけの`time`要素。ラベルの下の値はラベルと同じ左揃え・`tabular-nums`で表示する（制作2回目のKenの決定）。Clientが閲覧できる注文だけが集計対象となる点は確定しているが、キャンセル・返品を含めるか、購入回数を注文数と購入単位のどちらで数えるかは未確定。制作例の固定値で集計条件を確定しない。

### 注文履歴

| 項目・まとまり | 内容・表示 | 区分 |
|---|---|---|
| 注文の概要 | 注文番号・注文日時・店舗・合計金額（税込）・発送状況 | 表示項目と新しい順は案 |
| 注文者情報 | その注文時点の氏名・住所・電話番号 | 確定。メールアドレス・フリガナ等の項目詳細は未確定 |
| 届け先 | その注文で確定した届け先 | 確定。表示する項目の詳細は画面制作前に確認 |
| 受注一覧へのリンク | 対象の注文を受注一覧で確認するためのリンク | リンクは確定。受注一覧のキーワード（注文番号）で絞り込んだ状態で開く案。URLの形は未確定 |

注文者情報・届け先は、それぞれ見出しの下を「氏名」「〒郵便番号 住所」「電話番号」の3段落で表示する。項目ラベル・`dl`・`address`は使わず、長い住所は2段落目の中で省略せず折り返す。この2つのまとまりは見出しを含めて`fz(14)`とし、基本情報の箱の文字サイズは維持する。834pxより広い幅は横並び、834px以下だけ縦並び。以上は制作2回目のKenの決定。

注文概要の合計金額もラベルの下に左揃えで表示し、`tabular-nums`を維持する。受注一覧への導線は箱の右下の`a`要素とし、「詳細検索」と同じ白地・枠線のボタンの見た目、高さ44px以上とする。見た目がボタンでも`button`や`role="button"`には変えない。

## 未確定事項

- 購入回数・購入金額の合計にキャンセル・返品を含めるか。詳細での集計表示を追加する場合も[SPECの未確定事項](../SPEC.md#顧客管理の未確定事項)に従う
- 購入回数を、店舗ごとに分かれた注文の数で数えるか、購入の単位で数えるか。1回の購入で同じパートナーの複数店舗から買う場合を含めて決める
- 最新の注文がキャンセル・返品だった場合に、その注文者情報を基本情報に使うか
- 会員アカウントとの関係、メールアドレス変更時の扱い、注文者情報の項目詳細
- 店舗での絞り込みを詳細内に置くか。注文履歴へ店舗を表示する案とは分けて判断する
- 顧客詳細のURLやパラメータにはメールアドレスを出さない。顧客テーブルのIDなどの識別方法と、受注一覧へ移るURLの形
- 注文履歴の表示単位を常時展開・折りたたみ・ページ送りのどれにするか。件数が多い場合の扱い
- 基本情報に住所を表示するか、購入状況を同じ箱の下部に置くか。現行の制作例では案として表示する
- 顧客の識別方法が決まった後の、未存在・権限外・取得失敗の判定とHTTP応答。見つからない状態の共通表示は現時点では画面の案
- 社内用メモを将来追加するか。今回は置かない

## 制作記録（2026-10-21・1〜2回目の現行構成）

### 編集元・読み込み・URL

- [customer-detail.php](../../shop-partner/customer-detail.php)、[customer-detail.scss](../../shop-partner/assets/scss/customer-detail.scss) → [customer-detail.css](../../shop-partner/assets/css/customer-detail.css)

| 状態 | URL | 表示 |

`preview`・表示例の配列・固定の集計値は制作確認専用で、Laravel・Bladeへそのまま移さない。実データ・識別子・閲覧範囲をバックエンドで結び付ける。

### class・構成と見た目の案

- ページは`.customer-detail-page`。見出し近くの`.back-link`を右側に置き、保存バーは作らない
- `.form-box`は店舗フォームの白地・外枠・2.4remの余白を基準に、詳細のSassだけに記述。`.customer-profile`内の`.profile-list`は`dl`のラベル／値で表示し、`.profile-help`で最新情報の範囲を説明する
- 基本情報の住所は`.postal-code`と住所を表示する案。`.purchase-summary`も同じ箱の下部に3列で表示する案
- `.customer-history`に注文ごとの`section.history-order`を並べる。注文番号はh3、`.order-summary`に日時・店舗・税込金額、`.order-status`のラベルと`.shipping-status`に発送状況を表示する
- 発送状況は`status-new`・`status-processing`・`status-shipped`・`status-return`・`status-cancelled`と既存`$color-status-*`を対応させる。文言は新規受付・対応中・発送済・返品対応・キャンセル。`apply-status-box`は選択操作用のため呼ばず、ボタン・矢印・選択肢・`data-selectbox`・ホバー動作を持たないspanとする
- `.order-addresses`の`.address-group`は見出しごと`fz(14)`。`.contact-lines`の3つのpで氏名・郵便番号と住所・電話番号を表示し、`dl`・`dt`・`dd`・`address`は使わない。住所は省略せず折り返し、注文者と届け先を独立した値として保持する
- 横並びは`repeat(2, minmax(0, 1fr))`、`@media (max-width: $tb)`（834px）でだけ1列にする。旧1194pxの切り替えは使わない
- `.purchase-summary dd`と`.order-amount dd`は左揃え・`tabular-nums`。上部の`.profile-list`の文字サイズ・構成は変更しない
- `.order-actions a`は`button-base`を適用し、`inline-flex`で文字を中央に置く。白地・枠線・高さ4.4rem以上・共通のホバーとフォーカス枠を利用し、リンクの役割と右下の位置は維持する。共通Sassは変更しない
- ダミーの注文番号は`2610210112345`等の数字13桁とし、見出し・sectionの識別子・読み上げ補助・受注一覧URLのkeywordへ同じ値を使う。本番の採番方式やURLの契約を決めるものではない
- headの空favicon指定は制作2回目で削除。faviconは共通化時に検討し、今回ほかの画面や共通ファイルへ追加しない
- 通常のダミーは5件・2店舗・5状況。最新と過去の注文で住所と電話番号を変え、本人宛・ギフト・長い住所を含める。名前と店舗名はサンプル、メールは`example.com`、住所は架空県・サンプル町、郵便番号は000-0000、電話番号は000始まりを使う。一覧とは別の固定表示例で、データ連動はしない
- 回数5回・合計¥48,600、購入1回では1回・¥12,800は制作上の固定値。キャンセル・返品を含める判断はしていない。基本情報の最新値は、どちらも2026-10-21の新規受付の注文を参照する表示例

### 制作1回目当時の確認結果（2回目で表示構成を変更）

- `npm run sass`、DDEVの`php -l`（顧客詳細・書き出しスクリプト）、`git diff --check`を確認した

### 制作2回目の確認結果

- `npm run sass`、DDEVの`php -l`、`git diff --check`を確認した。静的出力はメモリ上で実行し、数字の注文番号と`orders.html?keyword=2610210112345`の一致を確認した
- Chrome・WebKitそれぞれで1280×800・1024×768・920×800・834×1194の通常・single・not-found・error（各16条件）を確認。横はみ出しなし、1280・1024・920pxは横並び、834pxは縦並びとなる
- 両住所情報は見出し付き・ラベルなしの3段落で、郵便番号と住所を同じ段落内に続け、長い住所を全文折り返す。`fz(14)`の実表示は1280・1024pxで14px、920pxで約13.44px、834pxで既存の下限12px。基本情報は従来の文字サイズを維持した

- 状態の表示・5種類のバッジ・サイドバー現在地を維持。ページのJSエラーとCSS／JS等の取得エラーはない。ただし空favicon指定の削除により、Chromeの初回読み込みで共通の`/favicon.ico`の404が1件発生する。WebKitでは発生しなかった。faviconは共通化時の検討事項として残し、ほかの画面や共通ファイルは修正していない
