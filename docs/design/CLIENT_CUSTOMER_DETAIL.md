# Client 顧客詳細 — 構成・項目の検討

## 位置づけ

2026-10-21のKenの決定を基に、Clientの顧客詳細を整理する画面資料。状態は「仕様検討中」。今回は資料だけを作成し、PHP・HTML・Sass・CSS・JSは作成しない。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。購入時点の情報と最新情報を混同せず、未指定の項目やURLを推測で確定しない。

顧客の定義・メールアドレスによる集約・閲覧範囲・集計条件は[SPECの顧客管理の確定事項](../SPEC.md#顧客管理の確定事項)を正とし、本資料には業務仕様を重複して定義しない。一覧画面は[顧客一覧](CLIENT_CUSTOMER_LIST.md)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、共通構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)を参照する。バックエンドへの確認は[QA No.11](../QA_BACKEND.md#no11-顧客管理のデータ閲覧範囲会員との関係)にまとめる。

## 確定している前提（2026-10-21）

- 対象はClient。顧客情報は閲覧のみで、編集・保存操作を置かない
- 顧客一覧の末尾の「詳細」アイコンから対象の顧客詳細へ進む
- 電話番号は一覧の列には置かず、本詳細の基本情報と注文ごとの注文者情報で表示する。一覧のキーワード検索では電話番号を引き続き対象にする（2026-10-21 Kenの決定）
- 上部に顧客の基本情報として、そのClientが閲覧できる注文（所属パートナーの店舗の注文）のうち最新の注文で確定した注文者情報を表示する
- 注文履歴・購入回数・購入金額の合計・最終購入日も同じ範囲の注文だけを対象とし、ほかのパートナーの注文は表示にも集計にも使わない
- 注文ごとに、その購入時点の注文者情報と届け先を表示する。最新情報で過去の注文を上書きしない
- 届け先は顧客をまとめる条件に使わず、注文ごとの情報として注文履歴内に表示する
- 各注文から受注一覧へ進むリンクを置く

## 項目

### 基本情報（最新）

| 項目 | 内容・表示 | 区分 |
|---|---|---|
| 氏名 | Clientが閲覧できる注文のうち、最新の注文で確定した注文者の氏名 | 確定 |
| メールアドレス | 顧客をまとめている注文者のメールアドレス | 確定 |
| 電話番号 | Clientが閲覧できる注文のうち、最新の注文で確定した注文者の電話番号 | 確定 |
| その他の注文者情報 | Clientが閲覧できる注文のうち、最新の注文で確定した情報 | 住所・フリガナ等の項目詳細は未確定 |

### 注文履歴

| 項目・まとまり | 内容・表示 | 区分 |
|---|---|---|
| 注文の概要 | 注文番号・注文日・店舗・合計金額（税込）・発送状況 | 表示項目と新しい順は案 |
| 注文者情報 | その注文時点の氏名・住所・電話番号 | 確定。メールアドレス・フリガナ等の項目詳細は未確定 |
| 届け先 | その注文で確定した届け先 | 確定。表示する項目の詳細は画面制作前に確認 |
| 受注一覧へのリンク | 対象の注文を受注一覧で確認するためのリンク | リンクは確定。受注一覧のキーワード（注文番号）で絞り込んだ状態で開く案。URLの形は未確定 |

## 操作と状態

| 操作・状態 | 表示・動作 | 区分 |
|---|---|---|
| 初期表示 | 最新の基本情報と注文履歴を表示する | 確定 |
| 注文履歴を確認 | 注文ごとの概要・注文者情報・届け先を確認する | 確定 |
| 受注一覧で確認 | 対象の注文から、受注一覧のキーワード（注文番号）で絞り込んだ状態へ進む | 遷移は確定。絞り込み方法は案。URLの形は未確定 |
| 顧客一覧へ戻る | 顧客一覧へ遷移する | 導線は必要。配置は案 |
| 編集・保存 | 操作を表示しない | 確定 |
| 社内用メモ | 今回は表示・入力しない | 将来の案 |

顧客は注文履歴から成り立つため、通常の詳細に注文0件の状態は想定しない。データ不整合や取得失敗時の具体的な表示は、画面制作時に既存の状態部品で対応できるか確認する。

## 見た目の案（Kenが画面で調整・決定）

| 対象 | 案・確認内容 |
|---|---|
| 基本情報 | 商品・店舗フォームの白い箱を参考にするが、入力欄ではなくラベルと値の読み取り専用表示にする |
| 注文履歴 | 新しい注文順。注文番号・注文日・店舗・合計金額（税込）・発送状況を見出しとして、注文者情報と届け先を同じ注文の中にまとめる |
| 注文ごとの情報 | PCでは注文者情報と届け先を横並び、タブレットでは縦並びにする案。長い住所を省略せず折り返す |
| 受注一覧へのリンク | 注文番号付近または注文の右側へ文字リンクとして置き、受注一覧を注文番号で絞り込んだ状態で開く案 |
| 戻る導線 | 商品・店舗フォームの「一覧へ戻る」を参考にするが、保存バーは作らない |
| 発送状況 | 受注一覧と同じ文言・状態色を使い、詳細側では表示のみとする案 |

新しい色・余白・寸法のトークンはこの資料では確定しない。

## 未確定事項

- 購入回数・購入金額の合計にキャンセル・返品を含めるか。詳細での集計表示を追加する場合も[SPECの未確定事項](../SPEC.md#顧客管理の未確定事項)に従う
- 購入回数を、店舗ごとに分かれた注文の数で数えるか、購入の単位で数えるか。1回の購入で同じパートナーの複数店舗から買う場合を含めて決める
- 最新の注文がキャンセル・返品だった場合に、その注文者情報を基本情報に使うか
- 会員アカウントとの関係、メールアドレス変更時の扱い、注文者情報の項目詳細
- 店舗での絞り込みを詳細内に置くか。注文履歴へ店舗を表示する案とは分けて判断する
- 顧客詳細のURLやパラメータにはメールアドレスを出さない。顧客テーブルのIDなどの識別方法と、受注一覧へ移るURLの形
- 注文履歴の表示単位を常時展開・折りたたみ・ページ送りのどれにするか。件数が多い場合の扱い
- 社内用メモを将来追加するか。今回は置かない
