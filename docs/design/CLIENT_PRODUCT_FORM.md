# Client 商品詳細（登録・編集）— 構成・項目の検討

## 位置づけ

2026-10-20のKenの決定を基に、Clientの商品詳細（登録・編集）を1つのフォームとして整理する画面資料。今回は資料のみを作成し、PHP・HTML・Sass・CSS・JSは作成・変更しない。

「確定」はKenの決定（2026-10-20）に含まれる内容だけ、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。既存資料の共通仕様は参照元として扱い、この画面の未検証の見た目・寸法・入力条件を新たな確定事項にしない。

業務仕様は[仕様書](../SPEC.md)、一覧との関係は[Client商品一覧資料](CLIENT_PRODUCT_LIST.md)、見た目の基準は[デザイントークン](../../DESIGN_TOKENS.md)と[デザイン方針](DESIGN.md)を参照する。制作・共通部品は[実装連携ガイド](../coding/IMPLEMENTATION_REFERENCE.md)・[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)・[Client共通申し送り](../coding/HANDOFF_CLIENT_COMMON.md)を参照する。制作時はCodexが依頼範囲を作成し、Kenが調整、Claudeが確認する。

## 確定している前提（2026-10-20）

- 商品詳細と商品登録は同じフォームで作り、新規／編集の違いだけを切り替える
- レイアウトは1列で箱を縦に並べる。順番は「基本情報 → 商品画像 → 価格・在庫 → 配送 → 入稿 → 商品仕様（食品表示）→ 公開設定」
- 保存バーはメイン領域内に置き、`position: sticky; bottom: 0`で画面下に固定する。サイドバーの開閉・重ね表示と干渉させないため、`fixed`は使わない
- カテゴリ・規格は最初は使わず、空欄や空の枠も置かない。将来カテゴリは基本情報へ追加する想定とし、価格・在庫は独立した箱にして、規格追加時に箱ごと規格の表へ差し替えられる構成にする
- 価格は税込で入力・表示する。税抜・税額の計算と端数処理はバックエンドで行う
- 商品名・価格（税込）・消費税率は必須とする（Kenの決定、2026-10-20）
- 商品は販売店に紐付けて登録し、基本情報に必須の「販売店」セレクトを置く。1つのClient（パートナー）が複数の販売店を持ち、送料は販売店ごとに設定する
- 配送温度帯を食品の箱から独立した「配送」の箱へ移す。ラジオ「常温・冷蔵・冷凍」、必須、新規の初期値は常温とし、食品のオン・オフにかかわらず入力・保存する
- ページ全体を1回のPOSTで保存し、即時保存はしない。公開状態も保存と同時に反映する
- 削除・複製・下書きの操作は最初は置かない。受注履歴との整合のため削除せず非公開で運用し、下書きは非公開保存で代用する。削除が必要になった場合は最下部に確認ダイアログ付きで追加する
- 未保存の離脱は`beforeunload`で警告する。ページ固有JSをまず作り、あとからリファクタする方針とする

### 新規／編集の違い

| 対象 | 新規 | 編集 | 区分 |
|---|---|---|---|
| フォーム | 同じフォームを新規登録に使う | 同じフォームを既存商品の編集に使う | 確定 |
| 画面名・見出し | 「商品登録」 | 「商品編集」 | 案。SPECの「商品詳細」との名称統一は未確定 |
| サイドバーの現在地 | 「商品登録」 | 「商品一覧」 | 案 |
| ID | 未発番のため表示しない | IDを読み取り専用で表示 | 確定 |
| 登録日時・更新日時 | 未登録のため表示しない | 両方を読み取り専用で表示 | 確定。編集時の見出しの下などの位置は案 |
| 消費税率 | 未選択 | 保存済みの値を選択 | 確定。どちらも必須 |
| 公開状態 | 非公開が初期値 | 保存済みの公開／非公開を変更し、保存時に反映 | 確定 |
| 販売店 | 必須。販売店が1つなら自動選択する案。複数の場合の初期値は未確定 | 保存済みの販売店を表示する。登録後に変更できるかは未確定 | セレクト・必須・保存値の表示は確定。自動選択は案 |
| 配送温度帯 | 配送の箱で初期値は常温 | 保存済みの値を表示する | 確定。食品オン時だけの項目にはしない |
| サイズ区分 | 選んだ販売店で使用するサイズだけを並べる案。初期値・必須条件は未確定 | 保存済みの値を表示する。販売店を選び直す場合の選択肢・選択値の更新は未確定 | 配送の箱に常設するセレクトは案。編集時の保存値の表示は確定 |
| 製造者・販売者 | 選んだ販売店の情報を初期値として欄に入れ、書き換え可能にする案 | 保存済みの値を表示する。販売店を選び直す場合の初期値更新は未確定 | 販売店情報を初期値の参照元にする方針は確定。反映操作・書き換えは案 |
| その他の入力値 | 初期値が指定されていない項目は未確定 | 保存済みの値を各欄へ表示する | 編集時の表示は確定。未指定の新規初期値は未確定 |
| 保存成功後 | IDが付いた編集画面へ移り、上部に「商品を登録しました」 | 同じ画面の上部に「保存しました」 | 確定。メッセージは`role="status"` |

## 画面構成

### 箱と保存バー（確定）

| 順番 | 箱・領域 | 内容・構成 |
|---|---|---|
| 1 | 基本情報 | 商品の基本項目と必須の販売店セレクト。カテゴリは今は置かず、将来の追加先とする |
| 2 | 商品画像 | 販売用の商品画像。具体的な操作は下記の案で検討 |
| 3 | 価格・在庫 | 税込価格・消費税率・在庫。規格追加時に箱単位で差し替えられるよう独立させる |
| 4 | 配送 | 必須の配送温度帯。サイズ区分のセレクトを常に置くのは案 |
| 5 | 入稿 | 商品ごとの入稿設定。具体的な入力方法は案 |
| 6 | 商品仕様（食品表示） | 見出し位置にチェックボックス「この商品は食品です」。オンのときだけ入力欄を開く |
| 7 | 公開設定 | ラジオ「公開／非公開」 |
| 下部 | 保存バー | メイン領域内のsticky配置。「保存する」（`button-primary`）＋「一覧へ戻る」（リンク） |

### 上部・共通部品・導線（案／既存資料の参照）

- 共通ヘッダー・サイドバー・メイン領域、`.page-heading`・`.form-field`・`.form-check`・`.check-group`などを再利用する案。既存構造への収まりを制作時に確認する
- 上部は見出し → 編集時のID・登録日時・更新日時 → 保存完了またはエラーの案内とする案。ID・日時の位置は未決定だが、完了・エラーの案内を上部に出すことは確定
- 一覧の編集アイコンから同じフォームの編集状態へ入る。現行の仮リンク`#`は実装時に接続し、実URLはバックエンド組み込み時に確認する。新規への入口は既存サイドバー「商品登録」を使う案
- 保存バーに「一覧へ戻る」を置くことは確定。バー内の左右の配置や、上部にも戻るリンクを置くかは案。パンくずはSPECの未確定事項のままとする
- 一覧の公開バッジは表示専用。フォームの公開状態はラジオで操作し、バッジを操作部品へ転用しない（確定）

## 項目

### 基本情報・商品画像・価格と在庫・配送・入稿・公開設定

確定と案を項目ごとに分ける。必須・任意の指定がない項目は、推測で必須にしない。

| 箱 | 項目 | 入力方法・表示 | 必須・初期値・補足 | 区分 |
|---|---|---|---|---|
| 基本情報 | 商品名 | テキスト入力の案 | 必須（Kenの決定、2026-10-20）。文字数上限は未確定 | 必須は確定。入力方法は案 |
| 基本情報 | 販売店 | セレクト | 必須。販売店が1つの場合は自動選択する案。複数の場合の初期値は未確定 | セレクト・必須は確定。自動選択は案 |
| 基本情報 | 商品説明 | テキストエリアの案。リッチエディタにはしない案 | 必須・任意、文字数上限は未確定 | 案 |
| 商品画像 | 画像の選択・一覧 | ファイル選択と画像の並びを表示する案。1枚目をメイン画像（一覧のサムネイル）とする案 | 一覧に画像なしの表示があるため、0枚でも保存できる前提で検討する。今回は案として扱う | 案 |
| 商品画像 | 並べ替え | ドラッグに加えてキーボード操作できる「前へ／後ろへ」ボタンを用意する案 | 上限枚数・形式・容量・推奨比率・アップロード時点・削除確認は未確定 | 案 |
| 価格・在庫 | 価格（税込） | 税込で入力・表示 | 必須（Kenの決定、2026-10-20）。税抜・税額の計算と端数処理はバックエンド。入力可能範囲は未確定 | 必須・税込・計算担当は確定。入力可能範囲は未確定 |
| 価格・在庫 | 消費税率 | ラジオ「8%（軽減税率）」「10%（標準税率）」。`fieldset`・`legend`「消費税率」でまとめる | 必須。新規は未選択、編集は保存済みの値。補助文「食品は通常8%です」を常に表示 | 確定 |
| 価格・在庫 | 在庫数・在庫管理 | 在庫数の入力欄と「在庫を管理しない」チェックボックスの案。チェック時は在庫数欄を無効化する案 | 一覧の「—」＋`.sr-only`「在庫管理なし」の表示案へつなげる。採用・必須条件・初期値は未確定 | 案 |
| 配送 | 配送温度帯 | ラジオ「常温・冷蔵・冷凍」 | 必須。新規の初期値は常温、編集は保存済みの値 | 確定 |
| 配送 | サイズ区分 | セレクトを常に置き、選んだ販売店で使っているサイズだけを並べる案 | 補助文「サイズ別に送料を設定していない販売店では使いません」を表示する案。重さの上限を伝える「サイズには重さの上限もあります（例：60サイズは2kgまで）」も補助文の候補。必須にする条件は未確定 | 案 |
| 入稿 | 入稿の有無 | 商品ごとにラジオ「入稿あり／なし」を置く案 | 初期値は未確定。「あり」の場合に必須／任意を設定する欄と注文者向け説明文の欄も案 | 案 |
| 公開設定 | 公開状態 | ラジオ「公開／非公開」 | 新規は非公開。選択だけでは反映せず、フォームの保存と同時に反映 | 確定 |

消費税率は食品の箱のオン・オフと連動させない。食品をオンにしても税率を自動選択せず、オフにしても税率を変更しない（確定）。

### 販売店・配送と送料の関係

- 販売店別の送料表・サイズ・クール便追加料金・送料無料条件は[SPECの販売店と送料の確定事項](../SPEC.md#販売店と送料の確定事項)を参照する。商品フォームに送料表や商品ごとの送料無料設定は置かない
- 複数販売店の商品を一緒に購入した場合は注文を販売店ごとに分ける。同じ販売店内では、サイズ別でなければ1注文1回分、サイズ別なら注文内の最大サイズで1個口。温度帯が混ざる場合は冷凍＞冷蔵＞常温の順でまとめて1個口とする（確定）
- クール便の追加料金は販売店の各送料表（サイズ別なら各タブ）で設定する。送料は標準税率10%・税込表示で、商品価格の税率とは分けて扱う。計算・端数処理・税率ごとの内訳はバックエンドで決める
- クール便の上限サイズは業者で異なるため固定しない（確認時点でヤマトは120まで、佐川は140まで）。各送料表のクール便追加料金が空欄なら、そのサイズ（サイズ別でない場合はその販売店）は非対応とする。追加料金の空欄は保存時も許す。通常送料欄の「空欄は保存時にエラーにする案」とは区別する（確定、Kenの了承、2026-10-20）
- 配送用のサイズ区分は、将来追加候補の商品規格（サイズ・色等）とは別の項目。現段階で商品規格を導入する決定ではない
- 販売店を選び直したときのサイズ区分の選択肢・選択値と、販売者の初期値の更新方法は未確定。登録後に販売店を変更できるかも未確定

### 商品仕様（食品表示）（確定）

以下の必須条件は「この商品は食品です」がオンのときに適用するフォーム上の決定。ネット販売での法的な表示義務の範囲を確定したものではない。

| 項目 | 入力方法 | 必須・任意／初期値 |
|---|---|---|
| 名称 | テキスト | 必須 |
| 原材料名 | テキストエリア | 必須 |
| アレルゲン | 特定原材料と推奨品目のチェックボックス群＋「該当なし」＋その他の自由記入 | 1つ以上または「該当なし」が必須。その他の自由記入の検証条件は未確定 |
| 内容量 | テキスト | 必須 |
| 期限 | 種別のラジオ「賞味期限・消費期限」＋テキスト | 必須。種別の初期値は未確定 |
| 保存方法 | テキスト | 必須 |
| 製造者・販売者 | テキストエリア | 必須。選んだ販売店の情報を初期値として欄に入れ、書き換えられるようにするのは案 |
| 栄養成分表示 | エネルギー・たんぱく質・脂質・炭水化物・食塩相当量のテキスト5項目 | 任意 |

- アレルゲンの品目は改定があるため画面へ固定せず、バックエンドのマスタから出力する。制作用PHPでは表示例とする
- 販売店は名称・住所・連絡先などの販売者情報を持ち、「製造者・販売者」の初期値の参照元にする方針は確定。欄への具体的な反映・書き換えの操作は案とし、編集時は保存済みの値を表示する
- ネット販売での表示義務の範囲は熊日側への確認事項として残す

## 操作と状態

### 配送条件の注意表示（案）

- 配送温度帯を冷蔵・冷凍にしたとき、選んだ販売店とサイズ区分にクール便追加料金が設定されていなければ注意を出す案。サイズ別でない販売店では、1つの送料表のクール便追加料金で判断する
- 非対応であることの注意だけにするか、エラーとして保存を止めるかは未確定。下記の確定済みエラー表示は、エラーとする条件が決まった項目に適用する

### 食品の箱の開閉（確定）

- 見出し位置の「この商品は食品です」で入力欄を開閉し、オンのときだけ開く
- チェックボックスは`aria-controls`で入力領域を参照する。checkboxではサポートされないため、`aria-expanded`は付けない
- 食品の入力欄全体を1つの`fieldset`で囲む。開閉用チェックボックスはこの領域の外に置き、オフでも操作できるようにする
- オフのときは`fieldset`に`disabled`と`hidden`を付け、表示と送信の対象から外す。オンのときは両属性を外す
- 配送温度帯・サイズ区分は別の「配送」の箱に置き、食品のfieldsetの開閉・無効化の対象に含めない
- オフで保存したとき、既存の食品情報を破棄するか保持するかは未確定。バックエンドと決める。送信対象から外すことと、保存済みの値を削除することは分けて扱う
- 食品の箱の中にエラーがあれば、箱を開いてエラーを表示する
- 共通の`toggleAccordion`（ボタン用）は使わず、`product-form.js`（仮名）でチェック状態に合わせて`fieldset`の`disabled`・`hidden`を切り替える

### 保存・エラー・離脱（確定）

| 状態・操作 | 表示・動作 |
|---|---|
| 保存前 | ページ全体を1回のPOSTで保存する。入力やラジオの変更による即時保存は行わない |
| 保存する | 保存バーの`button-primary`を使う。新規／編集とも文言は「保存する」 |
| 送信中 | 保存ボタンを無効にし、「保存中…」と表示して二重送信を防ぐ |
| 新規の保存成功 | IDが付いた編集画面へ移り、上部に`role="status"`で「商品を登録しました」 |
| 編集の保存成功 | 同じ画面の上部に`role="status"`で「保存しました」 |
| エラー | 同じ画面で入力値を保持。上部のエラーのまとめへフォーカスを移し、まとめから各欄へリンクする |
| 各欄のエラー | 既存の`.form-error`と`aria-invalid`・`aria-describedby`を使う。食品の箱にエラーがあれば開く |
| 一覧へ戻る | 保存バー内のリンクで一覧へ戻る。未保存なら離脱警告の対象 |
| 未保存の離脱 | `beforeunload`で警告する。固有JSの作成方針・読み込み順は制作予定を参照 |

画像アップロードのタイミングは未確定。商品情報を一括保存する方針と、画像ファイルの転送を選択時に行うか保存時に行うかは分けて確認する。エラー後のファイル選択・画像保持の方法も、アップロード方式と合わせて制作時に確認する。

### 制作確認用の状態（案）

`preview`は制作用で、業務用のパラメータではない。名前・組み合わせは既存の命名に合わせて調整してよい。次は候補で、URLや実装の確定ではない。

| 候補 | 確認する内容 |
|---|---|
| `new` | 新規。ID・登録日時・更新日時なし、税率未選択、非公開、配送温度帯は常温。販売店・サイズ区分の初期表示も確認 |
| 通常（preview指定なし） | 編集。保存済みの販売店・サイズ区分・配送温度帯を含む入力値、ID・登録日時・更新日時 |
| `single-store` | 販売店が1つ。販売店の自動選択案と製造者・販売者の初期値案 |
| `multi-store` | 販売店が複数。セレクトと、選んだ販売店ごとのサイズ候補。選び直し時の更新方法は未確定 |
| `shipping-size` | サイズ別送料を使う販売店。使用サイズだけを並べるセレクトの案 |
| `shipping-no-size` | サイズ別送料を使わない販売店。サイズ欄の常設と補助文の案 |
| `no-stock` | 在庫管理なしの案。在庫数欄の無効状態 |
| `upload` | 入稿ありの案。必須／任意・注文者向け説明文の配置 |

## 未確定事項・次に決めること

### 業務・入力条件

- 商品名などの文字数上限、価格・在庫の入力可能範囲、未指定の新規初期値。商品名・価格（税込）・消費税率・販売店・配送温度帯の必須は確定済みとし、必須・任意の指定がない項目だけを確認する

- 冷蔵・冷凍の商品でクール便に対応しないサイズを選んだ場合の扱い。サイズ別でない販売店が非対応の場合も含め、エラーにして保存を止めるか、注意だけにするか
- 販売店の削除・停止時の商品の扱い、登録後に商品の販売店を変更できるか。販売店の項目詳細はSPECの未確定事項を参照する

- 在庫管理なしの採用と操作・一覧表示の案。在庫0のときに売り切れ表示のまま公開を続けるか、非公開にするか
- 「残りわずか」の基準値と、全商品共通にするか商品ごとにするか。一覧の在庫検索との対応
- 入稿の形式・容量・件数（受注一覧と共通の未確定事項）、名入れなど文字の入稿の有無と文字数。「入稿あり／なし」・必須／任意・説明文欄の案

- 更新日時の更新契機（商品保存だけか、注文による在庫減少も含むか）は一覧資料の未確定事項を継続する
