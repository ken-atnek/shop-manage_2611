# Client 受注一覧 — 構成・項目の検討

## 位置づけ

ユーザー提供の参考画像`CleanShot 2026-10-16 at 20.27.16.jpg`を基に、受注一覧の構成と確認事項を整理する。

本資料は、ユーザーが確認した現行の画面仕様と、未確定事項・初期参考画像の読み取りを分けて管理する。画像の見た目だけで業務仕様を確定しない。現行仕様と実装メモは本資料内に記載し、Git除外の画像・提案メモがなくても参照できるようにする。

## 確定している前提

- 対象はClientの受注一覧。Masterへの展開範囲は別途確認する
- 管理画面の対応対象はPC・タブレット。スマートフォン対応は現時点の対象に含めない
- タブレットの縦向き対応、最小対応幅、基準幅、ブレークポイントは未確定
- Clientのブランド色は熊日ロゴの緑を基準とする仮方針。JPEG抽出の近似値`#57BC76`と区別し、UIには淡い面`#EEF7F1`（サイドバー背景）、線・文字`#2E7A4E`（選択ナビの左バー・文字、KPI選択、リンク）を使う。選択ナビは白い背景とし、ブランド色で濃い面を塗らない。正式なコーポレートカラーとClientへの緑の割り当ては未確定。1行内の強い色の塊はステータスだけ、通常時の入力欄はグレー枠とする
- 共通レイアウト、フォーム、ボタン、テーブルは他画面へ再利用する
- 発送状況の変更とメモ編集は、受注一覧内で行う。保存方法は未確定
- 入稿画像は注文者が注文時に添付する。管理画面の一覧では商品明細ごとに届いた画像を確認・拡大表示・ダウンロードし、添付・差し替え・削除は行わない
- 発送状況と全体メモは注文単位、入稿画像は商品明細単位で管理する
- 発送状況の下に最終更新日時を表示する。発送状況の変更が保存された時点で更新し、メモ編集・入稿画像の確認やダウンロードとは分ける
- 一覧に表示する住所はお届け先住所とする
- ヘッダーは正式名称が決まるまで仮表記「熊日モール」を維持する。ロゴ画像は色の参考に限りヘッダーへ配置しない。キャラクターとその色は管理画面に使用しない

## 現在のデザイン方向：C案 v9.1（v9の構成を維持）

最新の配色方針は資料のみの更新。v9.1を含む既存画像のテラコッタと緑のステータスは旧仮配色のまま残し、今回の仮配色を反映した画像とは扱わない。HTML・Sassも変更していない。

- 上部KPI → 1行の検索バーと「詳細検索」 → 注文一覧の構成。操作列のパネル展開ボタンで、その注文内にメモ・入稿画像を開く。行クリックによる開閉は補助とする
- 列は「注文・お届け先｜商品｜進捗状況・更新日時｜操作」の4列。要対応理由列と本日発送・画像未添付等の補助状態表示を削除し、状態表示は進捗ステータスへ一本化する
- 列の見出しは一覧の上に1回だけ表示する。各注文を外枠1pxの箱にし、注文間に約12pxの間隔を置く。角丸・影は付けない。展開行は対象注文の箱の内側に置く。見出しとすべての注文で列幅・罫線位置をそろえる。ヘッダーは淡いグレー背景で中央寄せ
- 商品欄は「商品名｜個数｜小計」の明細テーブルとし、1商品1行。その下に「消費税」「合計（税込）」の集計行を罫線で分けて置く。個数・金額は右揃え・等幅数字。ラベルは細く小さいグレー、合計は数値だけ太く一回り大きくし、色を付けない
- #1030の比較例はマグカップ1点2,800円とタオル1点1,500円、消費税430円・合計4,730円。#1029は1,200円・税120円・合計1,320円、#1028は2点3,000円・税300円・合計3,300円。税・送料等の業務ルールは未確定であり、画面に説明を追加しない。送料行は設けない
- 販売用の商品画像は表示しない。入稿画像のサムネイルは確認用として展開行だけに表示する
- ヘッダー・サイドバー・KPI→検索→一覧の構造は維持。KPIと検索は影なしの1px枠・最小限の角丸。サイドバー背景は仮の`#EEF7F1`。リード文は本文色、リンクはClientの線・文字用の仮グリーン`#2E7A4E`とする
- ステータスは小さな色付き現在値＋白い開閉部分を維持し、更新日時を下に表示する。新規受付の仮配色はオレンジ`#A35A1A`へ変更。ステータスには青・緑を使わず、対応が必要なものほど強い色、終わったものは落ち着いた色とする。正式な状態名・選択肢・配色・保存方法は未確定。その他の割り当て案と白文字の条件は[DESIGN_TOKENS.md](../../DESIGN_TOKENS.md)を参照し、キャンセルの仮色に白文字は使わない
- 展開エリアは注文の箱の全幅を使う罫線付きの行と、ごく淡いグレー背景。入稿画像がある場合は左に入稿画像、右に通常グレー枠のメモと文字ボタン「保存」を置く。左右の縦線は上の「商品｜進捗状況」の罫線と同じ位置にそろえる。右上に文字リンク「注文詳細を見る」を置く（Clientの仮グリーン`#2E7A4E`。青にはしない）
- 入稿画像は入稿のある商品明細だけを表示する。商品名・約48px角の正方形サムネイル・ファイル名・拡大表示／ダウンロードのピクトグラムを配置。今回のモックは1商品につき1枚で、#1030のマグカップは`photo_01.jpg`のみ。タオルの「入稿なし」行は出さない。注文内のどの商品にも入稿がなければ入稿画像欄自体を出さない。受付枚数の上限は未確定
- 注文日は全注文で年月日（`2026/10/17`）表記。お届け先は氏名（太字）→〒・住所→TEL→メールの順。メールはラベルなしでアドレスだけを表示する。住所以外の参照元、特にメールを注文者／お届け先のどちらから取得するかは引き続き確認する
- 操作列は幅約56pxに絞り、空いた幅を商品列へ回す。約40pxのタップ領域を持つパネル展開ボタン1つだけとし、詳細の書類アイコンと独立したシェブロンは置かない。ピクトグラムは約22×18pxの横長・角丸なしの四角に、下側の細い帯を区切る線と、その上の小さな軸なしシェブロンを組み合わせる。閉じているときは下向き、開いているときは上向き。線の太さとサイズ感は拡大表示・ダウンロードとそろえ、軸付き矢印やトレイから出入りする形にはしない（v9.1）
- メモも入稿画像もない注文は薄いグレーの展開アイコン。どちらかがある注文は本文色の濃いグレー＋右上の約7pxの点とし、ブランド色・状態色は使わない。薄いアイコンも操作可能で、無効状態ではない。開いているボタンだけ、ごく淡いグレー背景と細い枠の押した状態にする
- 表示例：#1030＝入稿画像あり・濃い＋点・展開、#1029＝メモあり・濃い＋点・折りたたみ、#1028＝どちらもなし・薄い・折りたたみ。非展開時の中身の有無はこの方式で示す（メモと入稿画像の内訳は開いて確認する）
- ナビ・ヘッダー・見出しの飾りアイコンは置かない。ナビの選択中項目は白い背景＋仮グリーン`#2E7A4E`の細い左バー・文字。ヘッダーのサイト確認・ログアウトは文字だけ。検索・詳細検索・保存は文字ボタン、展開・画像の確認／ダウンロードはピクトグラムとする
- KPIは選択中の1枚だけを仮グリーン`#2E7A4E`の細い線・文字で強調し、濃い面は塗らない。本日の新規3件と表示3件を連動。全体8件の集計条件は未確定
- 本文18px前後の大きめの文字を維持。消費税・合計（税込）のラベルは一回り小さいグレー、合計の数値は太字を維持する

### 検索とKPIの連動

- 検索欄の右に文字ボタン「検索」、続けて文字「詳細検索」＋下向き開閉矢印を置く。モックでは詳細検索を閉じた状態とする

- Enterキー、詳細条件とKPI・キーワードの組み合わせ、解除時の入力値保持などの細部は未確定。「すべて表示」と入力欄だけのリセットを混同しない

## 入稿画像の用途とUI

注文者が注文時に添付した画像を制作時に参照・利用し、画像を商品に貼り付けて納品する運用を想定する。商品一覧などで扱う販売用の商品画像とは用途を分ける。

入稿画像は注文内の商品明細ごとに紐づく。管理画面の一覧では受領済みの画像を確認・拡大表示・ダウンロードし、管理側の添付・差し替え・削除操作は設けない。全体メモは注文単位で別に扱う。

同じ商品でも別の注文・別の商品明細に添付を共有せず、対象の明細に紐づける。

- 展開行の「入稿画像（注文者より）」欄には、入稿のある商品だけを表示する。商品名→約48px角のサムネイル・ファイル名→拡大表示とダウンロードのピクトグラムを配置する。今回は1商品1枚の表示例とし、受付枚数を1枚に確定しない
- 入稿のない商品の行は出さない。どの商品にも入稿がない注文は入稿画像欄自体を出さない。管理側の添付・差し替え・削除・一括ダウンロードのボタンや、警告・バッジは描かない
- 非展開時の中身の有無は、展開ボタンの濃さと点で示す方式で解決済み。メモのみでも同じ中身あり表示とし、開いて内訳を確認する
- 画像の表示中・読込失敗・ダウンロード操作不可等の表示は必要に応じて整理する。注文側のアップロードや保存のUIはこの一覧では扱わない
- 確認表示用のサムネイルと、制作に利用する原本の扱いはバックエンド担当者と仕様を揃える
- 本プロジェクトでは確認・ダウンロード操作のUI仕様を扱い、ファイルの取得処理等はバックエンド担当者が実装する

未確定事項：

- 許可するファイル形式、容量、件数（注文側の制限）
- 拡大表示の方式（モーダル等）
- 一括ダウンロードの要否（v9では描かない）
- ファイル名の規則（photo_01.jpg等は表示例）

## PC・タブレットのレイアウト検討

- PCは画像の全体構成を参考にし、検索欄の余白と一覧の情報量を調整する
- タブレットでは左ナビの開閉と検索条件の段組み変更を検討する。具体的な幅は端末・向きの確認後に決める
- テーブルが収まらない場合は一覧領域だけの横スクロールを候補とし、注文の対応関係が崩れないようにする
- ステータスメニューがスクロール領域で切れないこと、タッチとキーボードで操作できることを確認する
- 顧客名だけを過度に強調せず、注文日・番号・発送状況も追いやすい文字の強弱を検討する

## 次に決めること

発送状況とメモの一覧内編集、注文時の入稿・商品明細ごとの確認とダウンロード、発送状況の最終更新日時表示は確定。次は発送状況・メモの保存方法と入稿画像の未確定事項を確認する。

その後、税・送料・小計の定義、KPIの集計条件、検索の組み合わせと解除時の入力値、連絡先・メールの参照元、注文詳細への遷移先、タブレットの向きと基準幅を順に決める。入稿なし注文の展開レイアウトや長い商品名・複数画像受付時の表示も、実データ条件に合わせて確認する。

「発送状況」（既存仕様・検索項目）と「進捗状況」（現在の画面見出し）の正式な呼称は確認事項。状態の範囲と併せて確認し、現段階では自動統一しない。
