# Client 受注一覧 — 構成・項目の検討

## 位置づけ

ユーザー提供の参考画像`CleanShot 2026-10-16 at 20.27.16.jpg`を基に、受注一覧の構成と確認事項を整理する。

本資料は、ユーザーが確認した現行の画面仕様と、未確定事項・初期参考画像の読み取りを分けて管理する。画像の見た目だけで業務仕様を確定しない。現行仕様と実装メモは本資料内に記載し、Git除外の画像・提案メモがなくても参照できるようにする。

## 確定している前提

- 対象はClientの受注一覧。Masterへの展開範囲は別途確認する
- 管理画面の対応対象はPC・タブレット。スマートフォン対応は現時点の対象に含めない
- タブレットの縦向き対応、最小対応幅、基準幅、ブレークポイントは未確定
- Clientのブランド色は熊日ロゴの緑を基準とする仮方針。[提供ロゴSVG](reference/kumaniti-logo.svg)でKマークの緑`#00BC64`を確認済みだが、これは参照用でUIでは直接使わない。UIには色相約152°を基にした仮値の淡い面`#EEF9F4`（サイドバー背景）、線・文字`#097141`（選択ナビの左バー・文字、KPI選択、リンク）を使う。選択ナビは白い背景とし、ブランド色で濃い面を塗らない。正式なコーポレートカラーの指定値とClientへの緑の割り当ては未確定。1行内の強い色の塊はステータスだけ、通常時の入力欄はグレー枠とする
- 共通レイアウト、フォーム、ボタン、テーブルは他画面へ再利用する
- 発送状況の変更とメモ編集は、受注一覧内で行う。保存方法は未確定
- 入稿画像は注文者が注文時に添付する。管理画面の一覧では商品明細ごとに届いた画像を確認・拡大表示・ダウンロードし、添付・差し替え・削除は行わない
- 発送状況と全体メモは注文単位、入稿画像は商品明細単位で管理する
- 発送状況の下に最終更新日時を表示する。発送状況の変更が保存された時点で更新し、メモ編集・入稿画像の確認やダウンロードとは分ける
- 一覧に表示する住所はお届け先住所とする
- ヘッダーは正式名称が決まるまで仮表記「熊日モール」を維持する。ロゴ画像は色の参考に限りヘッダーへ配置しない。キャラクターとその色は管理画面に使用しない

## 現在のデザイン方向：C案（v9.1以降の資料更新を含む）

最新の配色方針と、以下のKPI・金額・不要要素の整理は資料のみの更新で、HTML・Sass実装時に反映する。v9.1を含む既存画像は旧配色・旧項目・旧金額のまま残し、現行仕様をすべて反映した画像とは扱わない。画像・HTML・Sassは変更していない。

- ページ見出しは「受注一覧」と日付（表示例：`2026年10月17日`）だけとし、リード文は置かない
- 上部KPI → 1行の検索バーと「詳細検索」 → 注文一覧の構成。操作列のパネル展開ボタンで、その注文内にメモ・入稿画像を開く。行クリックによる開閉は補助とする
- 列は「注文・お届け先｜商品｜進捗状況・更新日時｜操作」の4列。要対応理由列と本日発送・画像未添付等の補助状態表示を削除し、状態表示は進捗ステータスへ一本化する
- 列の見出しは一覧の上に1回だけ表示する。各注文を外枠1pxの箱にし、注文間に約12pxの間隔を置く。角丸・影は付けない。展開行は対象注文の箱の内側に置く。見出しとすべての注文で列幅・罫線位置をそろえる。ヘッダーは淡いグレー背景で中央寄せ
- 商品欄は「商品名｜個数｜小計」の明細テーブルとし、1商品1行。商品の小計は税込価格として扱う。その下に「送料」「合計（税込）」の2つの集計行を罫線で分けて置き、従来の消費税行は置き換える。個数・金額は右揃え・等幅数字。ラベルは細く小さいグレー、合計は数値だけ太く一回り大きくし、色を付けない
- 表示例の送料は各注文`¥800`。#2610170112345はマグカップ1点2,800円＋タオル1点1,500円＋送料800円＝合計5,100円。#2026110300002は小計1,200円＋送料800円＝合計2,000円。#2026110300003は2点の小計3,000円＋送料800円＝合計3,800円。800円は表示例であり固定送料の決定ではない。送料の計算方法・送料無料の条件・消費税の表示要否・端数処理などは未確定で、画面に未確定ルールの説明を追加しない
- 販売用の商品画像は表示しない。入稿画像のサムネイルは確認用として展開行だけに表示する
- ヘッダー・サイドバー・KPI→検索→一覧の構造は維持。KPIと検索は影なしの1px枠・最小限の角丸。サイドバー背景は仮の`#EEF9F4`。残るリンクはClientの線・文字用の仮グリーン`#097141`とする
- ステータスは現在値＋白い開閉部分を持つ`.select-customer-status`へ3件とも統一し、更新日時を下に表示する。選択肢はユーザー確認済みの「新規受付｜対応中｜発送済｜返品対応｜キャンセル」の5項目を維持する。正式な呼称（発送状況／進捗状況）と配色の本決定・保存方法は未確定。現在の実装は[DESIGN_TOKENS.md](../../DESIGN_TOKENS.md)の仮配色にそろえ、`scss/_ui.scss`の`apply-status-box`で現在値と選択肢の色を管理する
- ステータスの配色は2026-10-17に決定：新規受付`#C2410C`・対応中`#8A3FD1`・発送済`#3D7A1F`・返品対応`#D21F3C`・キャンセル`#3A3F46`、すべて塗り＋白文字。値は`scss/_colors.scss`の`$color-status-*`、詳細は[DESIGN_TOKENS.md](../../DESIGN_TOKENS.md)。旧方針のキャンセルの白背景＋枠は廃止
- 展開エリアは注文の箱の全幅を使う罫線付きの行と、ごく淡いグレー背景。入稿画像がある場合は左に入稿画像、右に通常グレー枠のメモと文字ボタン「保存」を置く。左右の縦線は上の「商品｜進捗状況」の罫線と同じ位置にそろえる。注文詳細へのリンクは置かず、受注詳細画面を新設する前提にも立たない
- 入稿画像は入稿のある商品明細だけを表示する。商品名・約48px角の正方形サムネイル・ファイル名・拡大表示／ダウンロードのピクトグラムを配置。今回のモックは1商品につき1枚で、#2610170112345のマグカップは`photo_01.jpg`のみ。タオルの「入稿なし」行は出さない。注文内のどの商品にも入稿がなければ入稿画像欄自体を出さない。受付枚数の上限は未確定
- 注文番号の前に「注文番号」というラベルは付けない。番号は先頭に`#`を付けた13桁の表示例（`#2610170112345`）とする。発番ルールは未確定。注文日時は年月日と時・分（`2026/10/17 09:30`）を表示し、注文・お届け先列の右側へ寄せる。同じ段に収まらない場合は日時を次の段へ折り返し、右寄せを維持する。お届け先は氏名（太字）→〒・住所→TEL→メールの順。メールはラベルなしでアドレスだけを表示する。住所以外の参照元、特にメールを注文者／お届け先のどちらから取得するかは引き続き確認する
- 操作列は幅約56pxに絞り、空いた幅を商品列へ回す。約40pxのタップ領域を持つパネル展開ボタン1つだけとし、詳細の書類アイコンと独立したシェブロンは置かない。ピクトグラムは約22×18pxの横長・角丸なしの四角に、下側の細い帯を区切る線と、その上の小さな軸なしシェブロンを組み合わせる。閉じているときは下向き、開いているときは上向き。線の太さとサイズ感は拡大表示・ダウンロードとそろえ、軸付き矢印やトレイから出入りする形にはしない（v9.1）
- メモも入稿画像もない注文は薄いグレーの展開アイコン。どちらかがある注文は本文色の濃いグレー＋右上の約7pxの点とし、ブランド色・状態色は使わない。薄いアイコンも操作可能で、無効状態ではない。開いているボタンだけ、ごく淡いグレー背景と細い枠の押した状態にする
- 表示例：#2610170112345＝入稿画像あり・濃い＋点、#2026110300002＝メモあり・濃い＋点、#2026110300003＝どちらもなし・薄い。ステップ4の初期表示は3件とも折りたたみ。非展開時の中身の有無はこの方式で示す（メモと入稿画像の内訳は開いて確認する）
- ナビ・ヘッダー・見出しの飾りアイコンは置かない。ナビの選択中項目は白い背景＋仮グリーン`#097141`の細い左バー・文字。ナビのホバーは白50%で、選択中（白）より弱くする。ヘッダーのサイト確認は文字リンク、ログアウトはブランド色の塗り＋白文字のボタン（ブランド色の塗りの唯一の例外）。検索・詳細検索・保存は文字ボタン、展開・画像の確認／ダウンロードはピクトグラムとする
- KPIは左から「すべて｜未着手｜発送待ち」の3枚を等幅で並べる。選択中の1枚だけを仮グリーン`#097141`の細い線・文字で強調し、濃い面は塗らない。未着手3件を選ぶ表示例と一覧見出し3件を連動させる。詳細な集計条件は未確定
- 文字サイズは共通の流動フォント方式に従い、画面幅に応じて変わる（本文は概ね12〜16px）。固定のpx値では規定せず、金額・ステータスなど読ませたい箇所は`fz()`で個別に大きくして、PC・タブレット横・縦で確認する。送料・合計（税込）のラベルは一回り小さいグレー、合計の数値は太字を維持する

### 検索とKPIの連動

- 検索欄の右に文字ボタン「検索」、続けて文字「詳細検索」＋下向き開閉矢印を置く。モックでは詳細検索を閉じた状態とする
- KPIと重複する範囲ドロップダウンは設けない。選択中のKPIでリストの対象を絞り、件数を一致させる
- KPIの表示例は左から「すべて 8件｜未着手 3件｜発送待ち 2件」。初期選択は「未着手」、すべてを選ぶと全件を表示する。未着手は受付済みで準備・制作等の作業を始めていない注文を表し、前日以前も含めて受付日では区別しない。「持ち越し」の区分は設けない。対象ステータスとの対応・発送待ちに作業中を含むか・重複等の詳細な集計条件は未確定。件数は架空の表示例で、旧「本日の新規」と旧「持ち越し」を合算して実件数を決定したものではない
- 一覧見出しには対象と件数を表示する（例：`注文一覧 3件 未着手を表示`）。見出し右の解除リンクと一覧下の件数表示は置かず、全件表示への切り替えはKPI「すべて」で行う
- Enterキー、詳細条件とKPI・キーワードの組み合わせ、KPI「すべて」選択時の検索入力値の扱いなどの細部は未確定。全件表示への切り替えと入力欄だけのリセットを混同しない

### 操作とアクセシビリティの実装メモ

ステップ4でステータス選択とパネル展開ボタンの属性・開閉を実装済み。KPI・詳細検索の切り替え、入稿画像・メモの中身と保存、行クリックは未実装。読み上げソフト・タッチ実機の検証は別途行う。

| 対象 | アクセシブルな名前・ツールチップ | 選択・開閉状態 |
|---|---|---|
| KPI「すべて」 | 可視ラベルと同じ`すべて 8件` | 未着手を選ぶ例では`aria-pressed="false"`。選択時は`true` |
| KPI「未着手」 | 可視ラベルと同じ`未着手 3件` | 初期表示では`aria-pressed="true"` |
| KPI「発送待ち」 | 可視ラベルと同じ`発送待ち 2件` | 表示例では`aria-pressed="false"` |
| #2610170112345の展開ボタン（閉じている） | `注文#2610170112345のメモ・入稿画像を開く（メモ・入稿画像あり）` | `aria-expanded="false"` |
| #2026110300002の展開ボタン（閉じている） | `注文#2026110300002のメモ・入稿画像を開く（メモ・入稿画像あり）` | `aria-expanded="false"` |
| #2026110300003の展開ボタン（閉じている） | `注文#2026110300003のメモ・入稿画像を開く` | `aria-expanded="false"` |
| 入稿画像の拡大 | `photo_01.jpgを拡大表示` | 拡大方式に応じて実装時に定義 |
| 入稿画像のダウンロード | `photo_01.jpgをダウンロード` | 開閉なし |
| 詳細検索 | 可視ラベルと同じ`詳細検索` | モックは`aria-expanded="false"` |

- アイコンだけのボタンには表の名前を`aria-label`等で付け、同じ内容のツールチップを用意する。中身ありの補足はメモまたは入稿画像の存在を表す共通表現で、両方が必須という意味にはしない
- 展開ボタンと詳細検索は`aria-controls`で対象領域を関連付け、開閉に合わせて`aria-expanded`と名前・ツールチップを更新する
- KPIはボタンとし、選択中の1つだけ`aria-pressed="true"`、その他は`false`にする。「すべて」も同じ方式で選択状態を伝え、切り替え時はリストの対象・見出しの件数も同期する。状態は属性で伝え、可視ラベルを選択／解除の文言に変えない
- 約40pxのタップ領域を確保し、キーボードフォーカスを表示する。点や濃淡だけに情報を依存させない
- 行クリックは補助とし、展開・ステータス・画像操作・保存のボタンや入力欄の操作時に行クリックが重なって動かないようにする

## 受注一覧の表示候補

画像は「注文日・番号／お客様情報／商品／個数／小計／発送状況」の6列と、注文ごとのメモ欄で構成されている。

| 表示単位 | 画像で確認できる項目 | 確認事項 |
|---|---|---|
| 注文 | 注文日、注文番号 | 表示形式、クリック操作の要否 |
| 顧客 | 氏名、郵便番号・住所、電話番号、メールアドレス | 注文者情報か配送先情報か、一覧に常時表示する範囲 |
| 商品明細 | 商品名、個数、小計 | 現行では税込の小計として扱う。規格情報・明細小計の算出条件は確認する |
| 注文金額 | 送料、税込合計 | 割引・手数料など追加の表示項目の要否。金額計算は本プロジェクトで実装しない |
| 発送状況 | 状態表示と選択メニュー | 一覧内で変更する。正式な選択肢、変更権限、保存・確認方法は未確定 |
| メモ | 複数行入力欄 | 一覧内で編集する。用途、閲覧できる人、文字数、保存単位・方法は未確定 |

- 本プロジェクトでは確認・ダウンロード操作のUI仕様を扱い、ファイルの取得処理等はバックエンド担当者が実装する
