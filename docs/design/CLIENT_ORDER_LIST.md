# Client 受注一覧 — 構成・項目の検討

## 位置づけ

ユーザー提供の参考画像`CleanShot 2026-10-16 at 20.27.16.jpg`を基に、受注一覧の構成と確認事項を整理する。

本資料は、ユーザーが確認した現行の画面仕様と、未確定事項・初期参考画像の読み取りを分けて管理する。画像の見た目だけで業務仕様を確定しない。現行仕様と実装メモは本資料内に記載し、Git除外の画像・提案メモがなくても参照できるようにする。

## 確定している前提

- 対象はClientの受注一覧。Masterへの展開範囲は別途確認する
- 管理画面の対応対象はPC・タブレット。スマートフォン対応は現時点の対象に含めない
- タブレットの縦向き対応、最小対応幅、基準幅、ブレークポイントは未確定
- Clientのブランド色は熊日ロゴの緑を基準とする仮方針。[提供ロゴSVG](reference/kumaniti-logo.svg)でKマークの緑`#00BC64`を確認済みだが、これは参照用でUIでは直接使わない。UIには色相約152°を基にした仮値の淡い面`#EEF9F4`（サイドバー背景）、線・文字`#097141`（選択ナビの左バー・文字、KPI選択、リンク）を使う。選択ナビは白い背景とし、ブランド色で濃い面を塗らない。正式なコーポレートカラーの指定値とClientへの緑の割り当ては未確定。1行内の強い色の塊はステータスだけ、通常時の入力欄はグレー枠とする
- 共通レイアウト、フォーム、ボタン、テーブルは他画面へ再利用する
- 発送状況の変更は受注一覧内で行う。展開行の中身（備考・入稿画像・キャンセル／返品の記録）は「備考・キャンセル／返品の記録の決定（2026-10-20）」を参照。旧「店舗が書くメモ」は廃止
- 入稿画像は注文者が注文時に添付する。管理画面の一覧では商品明細ごとに届いた画像を確認・拡大表示・ダウンロードし、添付・差し替え・削除は行わない
- 発送状況・備考・キャンセル／返品の理由は注文単位、入稿画像とキャンセル／返品の商品ごとのメモは商品明細単位で管理する
- 発送状況の下に最終更新日時を表示する。発送状況の変更が保存された時点で更新し、キャンセル・返品の記録の保存や入稿画像の確認・ダウンロードとは分ける
- 一覧に表示する住所はお届け先住所とする
- ヘッダーは正式名称が決まるまで仮表記「熊日モール」を維持する。ロゴ画像は色の参考に限りヘッダーへ配置しない。キャラクターとその色は管理画面に使用しない

## 現在のデザイン方向：C案（v9.1以降の資料更新を含む）

最新の配色方針と、以下のKPI・金額・不要要素の整理は資料のみの更新で、HTML・Sass実装時に反映する。v9.1を含む既存画像は旧配色・旧項目・旧金額のまま残し、現行仕様をすべて反映した画像とは扱わない。画像・HTML・Sassは変更していない。

- ページ見出しは「受注一覧」と日付（表示例：`2026年10月17日`）だけとし、リード文は置かない
- 上部KPI → 1行の検索バーと「詳細検索」 → 注文一覧の構成。進捗状況・操作列のパネル展開ボタンだけで、その注文の詳細（備考・入稿画像・キャンセル／返品の記録）を開閉する。行クリックによる開閉は作らない（Kenの決定）
- 展開行はGridの`grid-template-rows: 0fr → 1fr`によるアコーディオン。閉じた状態は`inert`とし、操作・読み上げの対象から外す。動きを減らす設定では即時開閉、それ以外は0.25秒・ease-outで開閉する。展開行の開閉にはhiddenを使わない（ステータスメニューのhiddenは別の処理として維持）
- 列は「注文・お届け先｜商品｜進捗状況・操作」の3列。進捗状況と操作を1列に統合する（Kenの決定）。要対応理由列と本日発送・画像未添付等の補助状態表示を削除し、状態表示は進捗ステータスへ一本化する
- 列の見出しは一覧の上に1回だけ表示する。各注文を外枠1pxの箱にし、注文間に約12pxの間隔を置く。角丸・影は付けない。展開行は対象注文の箱の内側に置く。見出しとすべての注文で列幅・罫線位置をそろえる。ヘッダーは淡いグレー背景で中央寄せ
- 商品欄は「商品名｜個数｜小計」の明細テーブルとし、1商品1行。商品の小計は税込価格として扱う。その下に「送料」「合計（税込）」の2つの集計行を罫線で分けて置き、従来の消費税行は置き換える。個数・金額は右揃え・等幅数字。ラベルは細く小さいグレー、合計は数値だけ太く一回り大きくし、色を付けない
- 表示例の送料は各注文`¥800`。#2610170112345はマグカップ1点2,800円＋タオル1点1,500円＋送料800円＝合計5,100円。#2026110300002は小計1,200円＋送料800円＝合計2,000円。#2026110300003は2点の小計3,000円＋送料800円＝合計3,800円。800円は表示例であり固定送料の決定ではない。送料の計算方法・送料無料の条件・消費税の表示要否・端数処理などは未確定で、画面に未確定ルールの説明を追加しない
- 販売用の商品画像は表示しない。入稿画像のサムネイルは確認用として展開行だけに表示する
- ヘッダー・サイドバー・KPI→検索→一覧の構造は維持。KPIと検索は影なしの1px枠・最小限の角丸。サイドバー背景は仮の`#EEF9F4`。残るリンクはClientの線・文字用の仮グリーン`#097141`とする
- ステータスは現在値＋白い開閉部分を持つ`.select-customer-status`へ3件とも統一し、更新日時を下に表示する。選択肢はユーザー確認済みの「新規受付｜対応中｜発送済｜返品対応｜キャンセル」の5項目を維持する。正式な呼称（発送状況／進捗状況）と配色の本決定・保存方法は未確定。現在の実装は[DESIGN_TOKENS.md](../../DESIGN_TOKENS.md)の仮配色にそろえ、`scss/_ui.scss`の`apply-status-box`で現在値と選択肢の色を管理する
- ステータスの配色は2026-10-17に決定：新規受付`#C2410C`・対応中`#8A3FD1`・発送済`#3D7A1F`・返品対応`#D21F3C`・キャンセル`#3A3F46`、すべて塗り＋白文字。値は`scss/_colors.scss`の`$color-status-*`、詳細は[DESIGN_TOKENS.md](../../DESIGN_TOKENS.md)。旧方針のキャンセルの白背景＋枠は廃止
- 展開エリアは注文の箱の全幅を使う上罫線付きの行と、ごく淡いグレー背景。横並びFlexで、左の入稿画像は中身に必要な幅（最大40%）、右の`.detail-notes`は`flex: 1; min-width: 0`で残り幅を使い、間に縦罫線を引く。右は上に表示専用の「備考（お客様より）」、下に条件付きの「キャンセル・返品の記録」を置き、間は内側用トークンの横罫線。画像なしなら右が全幅を使う。上の列との罫線位置合わせ・注文詳細リンク・店舗の自由メモは設けない
- 入稿画像は入稿のある商品明細だけを表示する。1商品に複数枚あり、商品名の下へ1ファイル1行で縦に並べる。約48px角の正方形サムネイル→ファイル名→拡大ボタン→ダウンロードリンク。表示例は#2610170112345のマグカップに`photo_01.jpg`・`photo_02.jpg`の2枚。タオルの「入稿なし」行は出さない。どの商品にも入稿がなければ画像欄自体を出さない。拡大は共通のネイティブ`dialog`、受付枚数の上限は未確定
- 注文番号の前に「注文番号」というラベルは付けない。番号は先頭に`#`を付けた13桁の表示例（`#2610170112345`）とする。発番ルールは未確定。注文日時は年月日と時・分（`2026/10/17 09:30`）を表示し、注文・お届け先列の右側へ寄せる。同じ段に収まらない場合は日時を次の段へ折り返し、右寄せを維持する。お届け先は氏名（太字）→〒・住所→TEL→メールの順。メールはラベルなしでアドレスだけを表示する。住所以外の参照元、特にメールを注文者／お届け先のどちらから取得するかは引き続き確認する
- 独立した操作列は設けず、進捗状況・操作列（14rem）の上にステータスと更新日時、その下端に約40pxのタップ領域を持つパネル展開ボタンを1つ置く。すべて横方向は中央ぞろえ。日時と展開ボタンは1.2rem以上あける。展開行が箱のすぐ下に開くため、押す場所と開く場所を近づける、というKenの判断（お届け先の下端配置と同じ考え方）。詳細の書類アイコンと独立したシェブロンは置かない。ピクトグラムは約22×18pxの横長・角丸なしの四角に、下側の細い帯を区切る線と、その上の小さな軸なしシェブロンを組み合わせる。閉じているときは下向き、開いているときは上向き。線の太さとサイズ感は拡大表示・ダウンロードとそろえ、軸付き矢印やトレイから出入りする形にはしない（v9.1）
- 備考・入稿画像・保存済みの記録のいずれかがある注文は本文色の濃いグレー＋右上の約7pxの点（has-content）。いずれもない注文は薄いグレーとし、開くと「備考・入稿画像はありません」を表示する。未保存の入力だけでは点を付けない。ブランド色・状態色は使わず、薄いボタンも操作可能。開いているボタンだけ淡い背景と細い枠を付ける
- 初期表示は全注文の詳細を閉じる（aria-expanded="false"・パネルはinert）。表示例：#2610170112345＝新規受付・備考あり・画像2枚・記録欄はhidden・濃い＋点、#2026110300002＝返品対応・備考あり・画像1枚・記入済みの記録欄あり・濃い＋点、#2026110300003＝新規受付・備考なし・画像なし・記録欄はhidden・薄い。内訳は開いて確認する
- ヘッダー・見出しの飾りアイコンは置かない。Clientナビには畳んだ状態でも識別できるLucideの機能アイコンを付け、開いた状態もアイコン＋文字とする（Kenの決定、2026-10-19）。サイドバーは深い緑の面とし、ナビの選択中項目は`#1E5A43`の面＋白文字600＋`#7BE0AE`の左バー、ホバーは白8%の面とする。詳細は`DESIGN_TOKENS.md`を参照。ヘッダーのサイト確認は文字リンク、ログアウトはブランド色の塗り＋白文字のボタン。検索・詳細検索・保存は文字ボタン、展開は独自ピクトグラム、入稿画像の拡大／ダウンロードはLucideの`zoom-in`／`download`とする
- KPIは左から「すべて｜未着手｜発送待ち」の3枚を等幅で並べる。選択中の1枚だけを仮グリーン`#097141`の細い線・文字で強調し、濃い面は塗らない。初期表示は「すべて」8件を選び、一覧見出し8件と連動させる（一覧は表示例として先頭3件のみ掲載）。詳細な集計条件は未確定
- 文字サイズは共通の流動フォント方式に従い、画面幅に応じて変わる（本文は概ね12〜16px）。固定のpx値では規定せず、金額・ステータスなど読ませたい箇所は`fz()`で個別に大きくして、PC・タブレット横・縦で確認する。送料・合計（税込）のラベルは一回り小さいグレー、合計の数値は太字を維持する

### 検索とKPIの連動

- 検索欄の右に文字ボタン「検索」、続けて文字「詳細検索」＋開閉矢印を置く。詳細検索は初期表示で閉じ、ボタンで開閉する。注文日（期間）・ステータス（複数選択）・電話番号・メールアドレス・商品名の5項目を置く
- KPIと重複する範囲ドロップダウンは設けない。選択中のKPIでリストの対象を絞り、件数を一致させる
- KPIの表示例は左から「すべて 8件｜未着手 3件｜発送待ち 2件」。初期選択は「すべて」で全件を表示する。未着手は受付済みで準備・制作等の作業を始めていない注文を表し、前日以前も含めて受付日では区別しない。「持ち越し」の区分は設けない。対象ステータスとの対応・発送待ちに作業中を含むか・重複等の詳細な集計条件は未確定。件数は架空の表示例で、旧「本日の新規」と旧「持ち越し」を合算して実件数を決定したものではない
- 一覧見出しには対象と件数を表示する（例：`注文一覧 8件 すべてを表示`）。見出し右の解除リンクと一覧下の件数表示は置かず、全件表示への切り替えはKPI「すべて」で行う
- 「条件をクリア」は詳細検索パネル内だけを空にし、キーワードとKPIの選択は維持する。クリア後は注文日の開始日へフォーカスを移す。全件表示への切り替えとは分ける
- Enterキーでの検索仕様、詳細条件とKPI・キーワードの組み合わせ、KPI「すべて」選択時の検索入力値の扱いなどの細部は未確定。特にKPI「未着手」＋ステータス「発送済」のような組み合わせの扱いは、KPI切り替えの実装時に決める

### 備考・キャンセル／返品の記録の決定（2026-10-20）

Kenの決定。これまでの「メモ（店舗が書く保存フォーム）」に関する記述はこの節で置き換える。

**展開行の中身**
| 区分 | 内容 | 表示する条件 | 編集 |
|---|---|---|---|
| 備考（お客様より） | お客様が注文時に入力した備考欄の内容 | 入力がある注文だけ。空なら欄ごと出さない | しない（表示のみ） |
| 入稿画像 | 従来どおり | 入稿のある商品だけ | しない |
| キャンセル・返品の記録 | 注文単位の「理由・対応メモ」＋全商品明細ごとの短いメモ | 発送状況が「キャンセル」「返品対応」のときだけ | 店舗が記入し、1つの保存ボタンで保存 |

- 店舗側の自由メモは当面設けない
- 理由・対応メモは任意（必須にしない）。キャンセルの確認ダイアログでは理由の入力を求めず、展開行で書く
- 商品ごとのメモは、複数商品の返品も考えられるため、その注文の全商品明細に欄を出す。各欄は2行程度の短文で任意、上限は仮で100文字
- 発送状況をキャンセル・返品対応以外へ戻したときは、記録欄を隠すが内容は消さない。キャンセル・返品対応へ切り替えた時点で、展開行内に記録欄が表示される（自動で展開行を開いたり、フォーカスを移したりはしない）
- 中身ありの判定（展開ボタンの濃い色と点、読み上げ名の「あり」）は、備考・入稿画像・保存済みの記録のいずれかがあるとき
- 備考も入稿画像もなく、記録欄も出ない注文は、展開ボタンを薄い色のまま残し、開いたときは「備考・入稿画像はありません」の1行だけを表示する
- 配置案：左に入稿画像、右の列を上下に分け、上に備考、下にキャンセル・返品の記録。画像がなければ右の列が全幅を使う
- 記録欄の入力欄は`rows`を指定せず、`field-sizing: content`で入力に合わせて伸ばす（最小2行・最大10行分、超えたら欄内スクロール）。商品ごとのメモの商品名ラベルはfz(14)（2026-10-20、Kenの提案）
- 展開ボタンの読み上げ名・titleは「注文#{番号}の詳細を開く／閉じる」。備考・入稿画像・保存済みの記録があるときだけ末尾に「（内容あり）」を付ける

## 入稿画像の用途とUI

注文者が注文時に添付した画像を制作時に参照・利用し、画像を商品に貼り付けて納品する運用を想定する。商品一覧などで扱う販売用の商品画像とは用途を分ける。

入稿画像は注文内の商品明細ごとに紐づく。管理画面の一覧では受領済みの画像を確認・拡大表示・ダウンロードし、管理側の添付・差し替え・削除操作は設けない。備考とキャンセル・返品の理由は注文単位、商品ごとの記録は商品明細単位で別に扱う。

同じ商品でも別の注文・別の商品明細に添付を共有せず、対象の明細に紐づける。

- 展開行の「入稿画像（注文者より）」欄には、入稿のある商品だけを表示する。商品名の下に1ファイル1行で縦に並べ、約48px角のサムネイル→ファイル名→拡大ボタンとダウンロードリンクを配置する。1商品に複数枚あり、今回はマグカップに2枚の表示例とする。受付枚数の上限は別途確認する
- 入稿のない商品の行は出さない。どの商品にも入稿がない注文は入稿画像欄自体を出さない。管理側の添付・差し替え・削除・一括ダウンロードのボタンや、警告・バッジは描かない
- 非展開時の中身の有無は、展開ボタンの濃さと点で示す方式で解決済み。備考・入稿画像・保存済みの記録のいずれかがあれば同じ中身あり表示とし、開いて内訳を確認する
- 画像の表示中・読込失敗・ダウンロード操作不可等の表示は必要に応じて整理する。注文側のアップロードや保存のUIはこの一覧では扱わない
- 確認表示用のサムネイルと、制作に利用する原本の扱いはバックエンド担当者と仕様を揃える
- 本プロジェクトでは確認・ダウンロード操作のUI仕様を扱い、ファイルの取得処理等はバックエンド担当者が実装する

未確定事項：

- 許可するファイル形式、容量、件数（注文側の制限）
- 一括ダウンロードの要否（v9では描かない）
- ファイル名の規則（photo_01.jpg等は表示例）

拡大表示の方式は共通のネイティブ`dialog`モーダルに決定。備考は表示のみ。キャンセル・返品の記録は`form method="post" action="" data-cancel-record`に理由と全明細のtextarea・submitの保存ボタンを置く。旧memo／order_idのフォームは削除。name・明細ID・送信先は表示例で、注文の識別方法もバックエンドと確認する。保存処理・保存後の表示はバックエンドが実装し、フロントで通信・疑似保存・完了表示は作らない。
