# Client 店舗の登録・編集 — 構成・項目の検討

## 位置づけ

2026-10-20のKenの決定を基に、Clientの店舗登録・編集と送料設定を1つのフォームとして整理する画面資料。状態は「仕様確定（制作前）」で、画面実装は未着手。今回決まった内容と、引き続き残る案・未確定事項を分けて記載する。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。案の配置や未指定の入力条件を確定扱いにしない。

店舗・送料・注文の業務仕様は[SPECの店舗と送料の確定事項](../SPEC.md#店舗と送料の確定事項)、規格は[SPECの運送会社の規格](../SPEC.md#運送会社の規格正の資料)、13区分と都道府県の対応・入力案は[SPECの店舗と送料の案](../SPEC.md#店舗と送料の案)を正とする。本資料には規格値・送料計算ルール・都道府県の対応表を複製しない。

導線は[店舗一覧](CLIENT_STORE_LIST.md)、保存・エラーの参考は[商品フォーム](CLIENT_PRODUCT_FORM.md#保存エラー離脱確定)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)・[実装連携ガイド](../coding/IMPLEMENTATION_REFERENCE.md)・[Client共通申し送り](../coding/HANDOFF_CLIENT_COMMON.md)を参照する。

## 確定している前提（2026-10-20）

- 対象はClient。店舗の登録・編集は1つのフォームで、新規／編集の状態を切り替える
- サイドバーは「店舗」1項目。一覧の「店舗を追加」から新規へ入り、一覧から編集へ進む
- 基本情報の範囲・必須／任意、特定商取引法の表示の単位、食品表示への初期値挿入案の取り下げ、初期対象の運送会社は[SPECの確定事項](../SPEC.md#店舗と送料の確定事項)に従う
- 送料の設定はこのフォームに含める。[SPECの入力条件と初期値](../SPEC.md#店舗フォームの入力条件と初期値)・[変更と送信](../SPEC.md#配送送料の変更と送信)を正とする。金額保持・送信対象を画面側で別に定義しない
- 商品フォームのラベル・選択肢・判定と注意の表示文言は「店舗」へ変更済み（2026-10-20）。サイドバーの表示文言は今回の対象外で、次回変更する。`store_id`・`#product-store`・`store-shipping-data`・JSONのキーなど、コードの名前は変更しない

### 新規／編集の違い

| 対象 | 新規 | 編集 | 区分 |
|---|---|---|---|
| フォーム | 店舗を新規登録する | 対象の店舗を編集する | 同じフォームを使うことは確定 |
| 見出し | 「店舗登録」 | 「店舗編集」 | 確定 |
| ID・更新日時 | 未登録のため表示しない | 商品フォームと同様、見出しの下のメタ情報として読み取り専用で表示。日時は`time`要素を使う | 確定。登録日時の追加は今回決めていない |
| 基本情報 | 空欄から入力する案 | 保存済みの値を表示する案 | 案 |
| 配送・送料・送料無料 | SPECの新規初期値を表示する | 保存済みの設定・金額を表示する | 初期値・変更時の保持と送信対象はSPECで確定 |
| 保存後の通知 | 編集画面の上部に「店舗を登録しました」 | 同じ画面の上部に「保存しました」 | 文言は確定。遷移はSPECを参照し、`role="status"`は商品フォームに合わせる案 |

## 項目

入力条件・初期値の正は[SPECの店舗フォームの入力条件と初期値](../SPEC.md#店舗フォームの入力条件と初期値)。下表は入力部品・表示を整理し、業務条件の数値や検証ルールは複製しない。指定がない部品の見た目は案とする。

| 箱 | 項目 | 入力・表示 | 確定範囲・参照先 |
|---|---|---|---|
| 基本情報 | 店舗名 | テキスト入力 | 必須・文字数上限はSPECで確定 |
| 基本情報 | 発送元の住所 | 「郵便番号」＋「住所（1行）」の2欄（確定） | 任意・社内連絡用。分割と入力条件はSPECを参照 |
| 基本情報 | 発送元の担当者 | テキスト入力 | 任意・文字数上限はSPECで確定 |
| 基本情報 | 発送元の電話番号 | `type="tel"`（確定） | 任意・入力の許容条件はSPECを参照 |
| 配送 | 運送会社 | 1社を選ぶセレクトの案。未選択の表示を用意する | 初期対象・必須・初期値はSPECで確定。「その他」は後回し |
| 配送 | サイズ別の有無 | 「サイズ別に送料を設定する」のチェック | 設定の意味・初期値・切り替え時の保持はSPECを参照 |
| 配送 | 使うサイズ | 選択した会社の候補をチェックで選ぶ案 | 規格の編集欄は置かない。初期選択と運送会社変更時の扱いはSPECで確定 |
| 配送 | サイズ・重量・クール便の条件 | 運送会社を選ぶと読み取り専用で表示する案 | 規格値は[SPEC](../SPEC.md#運送会社の規格正の資料)を参照。共通データを使う |
| 配送 | 追跡ページURL | 運送会社から決まるため手入力させない案 | 方針は確定。URLの具体形・画面表示の要否は未確定 |
| 送料 | 全国一律の入力補助 | 金額欄と「全都道府県に入力」 | 上書きの扱いはSPECで確定。入力欄・ボタンの配置は案 |
| 送料 | 地方別の入力補助 | 各区分に金額欄と「この地方に入力」 | 案。13区分の対応はSPECを参照 |
| 送料 | 都道府県の通常送料 | 都道府県ラベルと税込金額の入力欄 | 初期値・必須・金額範囲はSPECで確定 |
| 送料 | クール便の追加料金 | 冷蔵・冷凍を別の欄にし、対応温度帯だけ表示（確定）。ゆうパックは冷蔵だけ | 空欄と0円の意味・金額範囲はSPECを参照 |
| 送料 | ゆうパック160タブの冷蔵欄 | 冷蔵欄を表示し、「3辺合計150cmまで」を補助文として関連付ける（確定） | 金額の対応と取扱条件はSPECを参照。規格の上限を広げない |
| 送料無料の条件 | 設定の有無・条件金額 | チェックと「○円以上で送料無料」の金額欄 | 条件・初期値・金額範囲はSPECを参照。オフ時の入力値保持・送信は未確定 |

必須・任意の文字、ラベルと入力欄の関連付け、金額の単位「円（税込）」は既存フォームを基準にする案。店舗フォームのname・id・送信データの形は実装時に整理し、この段階では決めない。

## 操作と状態

### 配送・送料の操作

| 操作・状態 | 表示・動作 | 区分 |
|---|---|---|
| 運送会社を選択 | 規格を読み取り専用で表示し、候補サイズと対応温度帯の料金欄を示す | 案。規格の変更不可は確定 |
| 運送会社を変更 | SPECに従って切り替え、使用サイズから外れたサイズ名を注意文で知らせる。例：「120サイズを使用サイズから外しました」（例文は案） | サイズ名の注意表示は確定。確認なし・金額保持・復元・送信対象はSPECを参照 |
| サイズ別を切り替え | オンで使用サイズとタブ、オフでサイズ共通の送料表を表示する | 確定。両方式の保持と非選択方式の扱いはSPECを参照 |
| 使用サイズを外す | 対象サイズのタブを表示対象から外す | 送信対象外は確定。手動で外して再選択する場合の保持方法は未確定 |
| タブを切り替え | 選択中の方式・使用サイズのタブだけを切り替える。非表示タブの入力も保存対象に残す | 確定。方式の非表示との違いは下表を参照 |
| 全国・地方への入力 | 実行後に「○件に入力しました」を`aria-live="polite"`で通知する。件数は反映した都道府県欄の数 | 通知は確定。確認なしの上書きはSPECを参照。サイズ別では表示中のタブを対象にする案 |
| クール便の追加料金 | 冷蔵・冷凍を分け、運送会社の対応温度帯の欄だけ表示する | 確定。金額の意味はSPECを参照 |
| 削除・停止 | 最初は操作を置かない | 案。店舗停止時等の商品の扱いは未確定 |

### 非表示領域と送信対象（確定）

以下は[SPECの送信仕様](../SPEC.md#配送送料の変更と送信)を画面の状態に対応させたもの。保存前の画面内保持と、POST後の保存済みデータの扱いは区別する。

| 領域 | 表示・属性 |
|---|---|
| 選んでいない送料方式 | `disabled`＋`hidden`で非表示・送信対象外。画面内の金額は保持する |
| 選択中の方式の、使用サイズの非表示タブ | `hidden`のみ。入力値を保持し、表示中のタブと一緒に送信する |
| 使用サイズから外れた分 | 表示・送信対象外。運送会社の変更で外れた金額はSPECに従って画面内で保持する |

### 保存・エラー・離脱（確定事項と商品フォームに合わせる案）

送信対象・保存後の遷移と完了文言は確定済み。それ以外の保存バーやエラー・離脱の操作は引き続き商品フォームに合わせる案。

| 操作・状態 | 表示・動作 |
|---|---|
| 保存前 | 基本情報・配送・送料・送料無料条件を同じフォームにまとめ、即時保存はしない |
| 保存する | メイン領域内の画面下にstickyの保存バーを置き、「保存する」で送信する |
| 送信中 | 保存ボタンを無効にして「保存中…」と表示し、二重送信を防ぐ |
| 保存成功 | 上部の通知は[新規／編集の違い](#新規編集の違い)の確定文言を使う。`role="status"`は案 |
| 入力エラー | 送信対象の各タブの入力値を保持する案。上部に件数と各欄へのリンクをまとめ、そこへフォーカスを移す |
| 非表示タブのエラー | 選択中の方式の使用サイズタブに印・件数を出し、まとめから該当タブを開いて入力欄へ移動する案 |
| 各欄のエラー | 共通の`.form-error`・`aria-invalid`・`aria-describedby`を利用する |
| 戻る・離脱 | 一覧へ戻るリンクを保存バーへ置く。変更後の未保存離脱は`beforeunload`で警告する |
| 送信失敗・復帰 | 再操作できる状態に戻す案。POST後の非送信データの復元はバックエンドと確認する |

タブのARIA・キーボード操作案は[SPEC](../SPEC.md#店舗と送料の案)を参照する。未確定の検証条件を、エラー表示案だけを理由に必須化しない。

## 見た目の案（Kenが画面で調整・決定）

| 対象 | 案・確認内容 |
|---|---|
| 箱 | 商品フォームの白い面・罫線・見出しを基準に、基本情報→配送→送料→送料無料の順に縦に並べる |
| 基本情報 | PCではラベルと入力を横に、タブレットでは縦にする既存フォームの配置を候補にする |
| 規格表示 | 会社選択の近くで、入力欄と区別した読み取り専用の一覧・補助文にする |
| 送料表 | 佐川の13区分ごとに見出しを付け、その下に都道府県の入力欄を並べる。各区分に「この地方に入力」を置く |
| PC／タブレット | 送料欄はPC幅3列・タブレット2列で確定。列間の余白・ラベル・単位の収まりを画面で調整する |
| タブ | 使用サイズが多い場合の収まり、選択中・フォーカス・エラーの見分け、入力途中の切り替えを確認する |
| 追加料金 | 通常送料の後へ置き、空欄の意味を説明する案。温度帯別の欄とゆうパック160タブの補助文は確定済み |
| 保存バー | 商品フォームのメイン内stickyを参照。最後の入力欄やフォーカスを隠さず、サイドバーと干渉しないか確認する |

この資料では新たなデザイントークンを確定しない。

## 未確定事項・次に決めること

- 手動の使用サイズ解除・再選択、送料無料オフ時の条件金額の保持・送信など、今回決めていない条件は[SPECの未確定事項](../SPEC.md#店舗と送料の未確定事項)を参照
- 郵便番号・住所・電話番号の未指定の入力条件、温度帯別料金を商品フォームの判定用JSONへ連携する方法
- 一括入力の対象タブ、箱・部品・保存バーの配置案、エラー・離脱の操作案、長いサイズタブの収まり、登録日時を追加表示するか。見出し・保存後の文言・IDと更新日時・送料欄の列数は確定済み
- 非送信データの保存後の扱いと、サーバーエラー後の復元。画面内の保存前の金額保持・送信対象は確定済みで、[バックエンドへの確認事項No.3](../SPEC.md#バックエンドへの確認事項)では永続データの扱いを確認する
- お客様の画面（購入画面）への店舗名表示は、同No.3の回答後に決める。表示する場合、店舗名はお客様向けの名前になる
- 「その他」は初期対象外として後回し。独自サイズ・重さ・温度帯条件の設定方法は未確定
- 削除・停止時の商品の扱い、離島の追加料金、Masterでの扱い、ゆうパックの横倒し不可時の判定、規格データの持ち方などは[SPECの未確定事項](../SPEC.md#店舗と送料の未確定事項)を参照する
- パートナー情報画面の制作時期は未定。特定商取引法の表示設定は店舗フォームへ追加しない
