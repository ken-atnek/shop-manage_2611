# Client 店舗の登録・編集 — 構成・項目の検討

## 位置づけ

2026-10-20のKenの決定を基に、Clientの店舗登録・編集と送料設定を1つのフォームとして整理する画面資料。状態は「完成（引き渡し前）」（2026-10-21）。箱・項目・初期状態、配送・送料の切り替えに加え、保存送信・送信中・エラー・保存後の通知・未保存離脱警告を制作済み。保存先は`action="#"`のままで、バックエンド処理・入力検証は実装しない。今回決まった内容と、引き続き残る案・未確定事項を分けて記載する。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。案の配置や未指定の入力条件を確定扱いにしない。

店舗・送料・注文の業務仕様は[SPECの店舗と送料の確定事項](../SPEC.md#店舗と送料の確定事項)、規格は[SPECの運送会社の規格](../SPEC.md#運送会社の規格正の資料)、13区分と都道府県の対応・入力案は[SPECの店舗と送料の案](../SPEC.md#店舗と送料の案)を正とする。本資料には規格値・送料計算ルール・都道府県の対応表を複製しない。

導線は[店舗一覧](CLIENT_STORE_LIST.md)、保存・エラーの参考は[商品フォーム](CLIENT_PRODUCT_FORM.md#保存エラー離脱確定)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)・[実装連携ガイド](../coding/IMPLEMENTATION_REFERENCE.md)・[Client共通申し送り](../coding/HANDOFF_CLIENT_COMMON.md)を参照する。

バックエンドへの接続内容は[店舗フォームの申し送り](../coding/HANDOFF_CLIENT_STORE_FORM.md)を参照。送信項目・DBとの差異・JSON・JS依存先・検証範囲を整理済み。実際の引き渡し・Blade組み込みはこれから行う。

## 確定している前提（2026-10-20）

- 対象はClient。店舗の登録・編集は1つのフォームで、新規／編集の状態を切り替える
- サイドバーは「店舗」1項目。一覧の「店舗を追加」から新規へ入り、一覧から編集へ進む
- 基本情報の範囲・必須／任意、特定商取引法の表示の単位、食品表示への初期値挿入案の取り下げ、初期対象の運送会社は[SPECの確定事項](../SPEC.md#店舗と送料の確定事項)に従う
- 送料の設定はこのフォームに含める。[SPECの入力条件と初期値](../SPEC.md#店舗フォームの入力条件と初期値)・[変更と送信](../SPEC.md#配送送料の変更と送信)を正とする。金額保持・送信対象を画面側で別に定義しない
- 商品フォームのラベル・選択肢・判定と注意の表示文言は「店舗」へ変更済み（2026-10-20）。サイドバーは一覧制作時に「店舗」へ変更済みで、店舗フォームも同じ現在地を使う。`store_id`・`#product-store`・`store-shipping-data`・JSONのキーなど、コードの名前は変更しない

### name・idの仮案（2026-10-21）

以下は表示を組み立てるための仮案。[DB設計](../backend/DB_DESIGN.md)との対応を示すが、本番のAPI・送信契約を確定するものではない。`{size}`はcm値、`{code}`は2桁の都道府県コード、`{region}`は制作用配列の地方キー。

| 項目 | name（仮） | id（仮） |
|---|---|---|
| 店舗名 | `name` | `store-name` |
| 郵便番号 | `postal_code` | `store-postal-code` |
| 住所（1行） | `address` | `store-address` |
| 担当者 | `contact_name` | `store-contact-name` |
| 電話番号 | `phone` | `store-phone` |
| 運送会社 | `carrier_code` | `store-carrier` |
| サイズ別の有無 | `size_based` | `store-size-based` |
| 使用サイズ | `used_sizes[]` | `store-size-{size}` |
| サイズ共通の通常送料 | `shipping_tables[common][rates][{code}][base_fee_yen]` | `shipping-common-pref-{code}` |
| サイズ別の通常送料 | `shipping_tables[by_size][{size}][rates][{code}][base_fee_yen]` | `shipping-size-{size}-pref-{code}` |
| 冷蔵追加料金 | 上記の表の接頭辞＋`[cool_refrigerated_surcharge_yen]` | `shipping-common-refrigerated` / `shipping-size-{size}-refrigerated` |
| 冷凍追加料金 | 上記の表の接頭辞＋`[cool_frozen_surcharge_yen]` | `shipping-common-frozen` / `shipping-size-{size}-frozen` |
| 送料無料の有無 | `free_shipping_enabled` | `store-free-shipping` |
| 送料無料の条件金額 | `free_shipping_threshold_yen` | `store-free-shipping-threshold` |
| 全国一律の入力補助 | なし（保存項目に含めない） | `shipping-common-all` / `shipping-size-{size}-all` |
| 地方別の入力補助 | なし（保存項目に含めない） | 表のid接頭辞＋`-{region}-bulk` |

方式は`shipping-mode-common` / `shipping-mode-by_size`のfieldset、サイズタブは`shipping-tab-{size}`、パネルは`shipping-panel-{size}`。各タブとパネルをARIAで関連付ける。

DBとの相違は、`carrier_code`が`stores.carrier_id`ではなく会社コード、`used_sizes[]`が`carrier_size_id`ではなくcm値である点。ネストした送料は本番の`store_shipping_tables`・`store_shipping_rates`へ対応付けが必要。`free_shipping_enabled`は画面用の仮項目で、DBには独立列がない。DBの閾値NULL＝不使用との対応付けはバックエンド組み込み時に確認する。画面内でのオフ時の値保持・disabledによる非送信は2026-10-21に確定した。`partner_id`・店舗IDなどはフォームの自由入力には追加せず、所属・更新対象の判定はバックエンドが行う。

基本情報・通常送料・温度帯別追加料金の項目はDB設計と一致。郵便番号・電話番号のDB上の長さは案のため、画面では未指定のmaxlengthやパターンを追加していない。制作用規格の`refrigerated`とDBの規格温度帯`cold`も本番データへの置き換え時に対応付ける（料金列名は一致）。

### 非表示領域と送信対象（確定）

以下は[SPECの送信仕様](../SPEC.md#配送送料の変更と送信)を画面の状態に対応させたもの。保存前の画面内保持と、POST後の保存済みデータの扱いは区別する。

| 領域 | 表示・属性 |
|---|---|
| 選んでいない送料方式 | `disabled`＋`hidden`で非表示・送信対象外。画面内の金額は保持する |
| 選択中の方式の、使用サイズの非表示タブ | `hidden`のみ。入力値を保持し、表示中のタブと一緒に送信する |
| 使用サイズから外れた分 | `disabled`＋`hidden`。運送会社の変更・手動解除のどちらも金額を画面内で保持する |

対象外のクール便欄も`disabled`＋`hidden`で値を保持する。送料無料の条件金額はオフで`disabled`にし、見えるまま保持する（2026-10-21確定）。

### 保存・エラー・離脱（2026-10-21確定・制作済み）

[商品フォーム2-Bの申し送り](../coding/HANDOFF_CLIENT_PRODUCT_FORM.md)と同じ仕組み・見た目を使う。送信対象・保存後の遷移の業務仕様はSPECを参照し、本番の保存処理・入力検証はバックエンドで実装する。

| 操作・状態 | 表示・動作 |
|---|---|
| 保存前 | 4つの箱を1つのPOSTフォームにまとめ、即時保存しない。`action="#"`・`novalidate`のまま |
| 保存する | 保存バーの`type="submit"`で通常のフォーム送信。入力欄のname・送信対象は2回目から変更しない |
| 送信中 | 保存ボタンだけをdisabledにして「保存中…」、formに`aria-busy="true"`。2回目のsubmitはpreventDefaultで止める |
| 保存成功 | ページ上部の`.save-status`に確定文言を`role="status"`で表示。フォーカスを移さない |
| 入力エラー | 入力値を保持したサーバー応答の想定をpreviewで表示。最初の有効なエラーがあるサイズタブを選択し、上部の`.error-summary`へ初期フォーカスを移す。件数はまとめの行数 |
| 非表示タブのエラー | 各パネルの有効な`aria-invalid="true"`欄を数え、タブに「!」と件数を表示。読み上げ名は「120サイズ、エラー2件」等。まとめから該当タブを選択して最初のエラー欄へ移動 |
| 各欄のエラー | 共通の`.form-error`・`aria-invalid="true"`・`aria-describedby`を使う。disabledの欄はまとめ・タブ件数・表示対象から除外。修正後も再保存の応答まではエラー属性を残す |
| 戻る・離脱 | input／changeと成功した一括入力で「変更あり」。変更を元に戻しても解除しない。未保存時だけbeforeunloadの標準確認を使い、保存送信時は解除 |
| 戻る操作からの復帰 | `pageshow.persisted`で送信状態・ボタン・aria-busyを戻す。未保存の変更がある場合は離脱警告を付け直す |

保存失敗の業務処理や、サーバー応答後の非送信データの復元詳細は今回の範囲外。未確定の検証条件をエラー表示だけを理由に追加しない。

### サイズ別送料の見た目（2026-10-21 Kenの決定・制作済み）

- サイズタブは送料の箱内で`position: sticky; top: 0`。白い背景と上1.2remの余白を付け、内容が透けないようにする。下線は既存の濃い枠線色。固定範囲はサイズ別のfieldsetまでで、送料の箱の外へ持ち出さない
