# Client 店舗の登録・編集 — 構成・項目の検討

## 位置づけ

2026-10-20のKenの決定を基に、Clientの店舗登録・編集と送料設定を1つのフォームとして整理する画面資料。状態は「仕様検討中」で、画面実装は未着手。

「確定」はKenの決定、「案」はKenが画面で調整・決定する内容、「未確定」は業務条件や今後の確認事項とする。案の配置や未指定の入力条件を確定扱いにしない。

店舗・送料・注文の業務仕様は[SPECの店舗と送料の確定事項](../SPEC.md#店舗と送料の確定事項)、規格は[SPECの運送会社の規格](../SPEC.md#運送会社の規格正の資料)、13区分と都道府県の対応・入力案は[SPECの店舗と送料の案](../SPEC.md#店舗と送料の案)を正とする。本資料には規格値・送料計算ルール・都道府県の対応表を複製しない。

導線は[店舗一覧](CLIENT_STORE_LIST.md)、保存・エラーの参考は[商品フォーム](CLIENT_PRODUCT_FORM.md#保存エラー離脱確定)、見た目は[デザイントークン](../../DESIGN_TOKENS.md)・[デザイン方針](DESIGN.md)、構造は[共通レイアウト](../coding/LAYOUT_TEMPLATE.md)・[実装連携ガイド](../coding/IMPLEMENTATION_REFERENCE.md)・[Client共通申し送り](../coding/HANDOFF_CLIENT_COMMON.md)を参照する。

## 確定している前提（2026-10-20）

- 対象はClient。店舗の登録・編集は1つのフォームで、新規／編集の状態を切り替える
- サイドバーは「店舗」1項目。一覧の「店舗を追加」から新規へ入り、一覧から編集へ進む
- 基本情報の範囲・必須／任意、特定商取引法の表示の単位、食品表示への初期値挿入案の取り下げ、初期対象の運送会社は[SPECの確定事項](../SPEC.md#店舗と送料の確定事項)に従う
- 送料の設定はこのフォームに含める。サイズ別設定とタブ、全タブを1回のPOSTで保存する方針もSPECに従う
- 今回は資料のみ。商品フォームのラベル・選択肢・判定と注意、サイドバーなどの表示文言は次回変更する。`store_id`・`#product-store`・`store-shipping-data`・JSONのキーなど、コードの名前は変更しない

### 新規／編集の違い

| 対象 | 新規 | 編集 | 区分 |
|---|---|---|---|
| フォーム | 店舗を新規登録する | 対象の店舗を編集する | 同じフォームを使うことは確定 |
| 見出し | 「店舗登録」 | 「店舗編集」 | 案 |
| 基本情報 | 空欄から入力する案 | 保存済みの値を表示する案 | 案 |
| 配送・送料・送料無料 | 未指定の初期値は確定しない | 保存済みの設定・金額を表示する案 | 初期値・変更時の扱いは未確定 |
| 保存後 | ID付きの編集画面へ移る案 | 同じ画面で完了を知らせる案 | 遷移・文言は未確定 |

## 画面構成

### 箱の順番（案）

| 順番 | 箱・領域 | 内容 |
|---|---|---|
| 上部 | ページ見出し・案内 | 新規／編集の見出し、完了通知またはエラーのまとめ |
| 1 | 基本情報 | 店舗名、社内連絡用の発送元住所・担当者・電話番号 |
| 2 | 配送 | 運送会社、サイズ別の有無、使うサイズ、読み取り専用の運送会社規格 |
| 3 | 送料 | 全国一律の入力補助、13区分の見出しと都道府県欄、クール便追加料金。サイズ別ならタブ |
| 4 | 送料無料の条件 | 設定の有無と条件金額。送料タブの外に置く |
| 下部 | 保存バー | 「一覧へ戻る」と「保存する」。商品フォームと同じ画面下の配置を候補にする |

特定商取引法の表示を設定する欄や食品表示の初期値設定欄は置かない。設定先・取り下げの根拠はSPECを参照する。

## 項目

項目の配置・入力部品は案。基本情報の必須／任意など、確定済みの業務条件はSPECを参照して示す。

| 箱 | 項目 | 入力・表示案 | 確定範囲・未確定事項 |
|---|---|---|---|
| 基本情報 | 店舗名 | テキスト入力 | 必須はSPECで確定。文字数上限は未確定 |
| 基本情報 | 発送元の住所 | 住所の入力欄 | 任意・社内連絡用はSPECで確定。郵便番号・住所の分割方法は未確定 |
| 基本情報 | 発送元の担当者 | テキスト入力 | 任意・社内連絡用はSPECで確定。文字数上限は未確定 |
| 基本情報 | 発送元の電話番号 | 電話番号入力 | 任意・社内連絡用はSPECで確定。入力形式は未確定 |
| 配送 | 運送会社 | 1社を選ぶセレクトの案 | 初期対象はヤマト運輸・佐川急便・ゆうパック。初期選択は未確定。「その他」は後回し |
| 配送 | サイズ別の有無 | 「サイズ別に送料を設定する」のチェック | 設定の意味はSPECを参照。初期値は未確定 |
| 配送 | 使うサイズ | 選択した会社の候補をチェックで選ぶ案 | 規格の編集欄は置かない。初期選択・サイズ解除時の扱いは未確定 |
| 配送 | サイズ・重量・クール便の条件 | 運送会社を選ぶと読み取り専用で表示する案 | 規格値は[SPEC](../SPEC.md#運送会社の規格正の資料)を参照。共通データを使う |
| 配送 | 追跡ページURL | 運送会社から決まるため手入力させない案 | 方針は確定。URLの具体形・画面表示の要否は未確定 |
| 送料 | 全国一律の入力補助 | 金額欄と「全都道府県に入力」 | 補助操作の意味はSPECで確定。上書き確認の有無は未確定 |
| 送料 | 地方別の入力補助 | 各区分に金額欄と「この地方に入力」 | 案。13区分の対応はSPECを参照 |
| 送料 | 都道府県の通常送料 | 都道府県ラベルと税込金額の入力欄 | 初期値空欄・全欄必須はSPECの案。範囲・桁は未確定 |
| 送料 | クール便の追加料金 | 対応する温度帯だけを表示する案。ゆうパックは冷蔵のみ | 空欄と0円の意味はSPECで確定。冷蔵・冷凍を別欄にするか1欄にするかは未確定 |
| 送料無料の条件 | 設定の有無・条件金額 | チェックと「○円以上で送料無料」の金額欄 | 条件の意味とタブ外の配置はSPECを参照。初期値・オフ時の入力値保持は未確定 |

必須・任意の文字、ラベルと入力欄の関連付け、金額の単位「円（税込）」は既存フォームを基準にする案。店舗フォームのname・id・送信データの形は実装時に整理し、この段階では決めない。

## 操作と状態

### 配送・送料の操作

| 操作・状態 | 表示・動作 | 区分 |
|---|---|---|
| 運送会社を選択 | 規格を読み取り専用で表示し、候補サイズと対応温度帯の料金欄を示す | 案。規格の変更不可は確定 |
| 運送会社を変更 | 使用サイズ・入力済み送料の消去／保持、確認の有無を検討する | 未確定。自動消去を前提にしない |
| サイズ別を切り替え | オンで使用サイズとタブ、オフで1つの送料表を表示する | 構成はSPECで確定。切り替え時の金額の保持・移行は未確定 |
| 使用サイズを外す | タブと入力済み送料の扱いを決めてから実装する | 未確定 |
| タブを切り替え | 入力値を保持し、全タブの内容を保存する | 確定。送信対象の扱いはSPECを参照 |
| 全国・地方への入力 | 対象の都道府県欄へ金額を入れる。サイズ別では表示中のタブを対象にする案 | 案。対象範囲の案内・上書き確認は未確定 |
| クール便の追加料金 | 対応する温度帯の欄を表示する。空欄と0円を区別して案内する | 表示は案。金額の意味はSPECを参照 |
| 削除・停止 | 最初は操作を置かない | 案。店舗停止時等の商品の扱いは未確定 |

### 保存・エラー・離脱（商品フォームに合わせる案）

全タブを1回のPOSTで保存することは確定済み。それ以外の見た目・操作は、今回の検討案として商品フォームを参照する。

| 操作・状態 | 案 |
|---|---|
| 保存前 | 基本情報・配送・送料・送料無料条件を同じフォームにまとめ、即時保存はしない |
| 保存する | メイン領域内の画面下にstickyの保存バーを置き、「保存する」で送信する |
| 送信中 | 保存ボタンを無効にして「保存中…」と表示し、二重送信を防ぐ |
| 保存成功 | 上部の`role="status"`で完了を通知する。遷移先と正式文言は未確定 |
| 入力エラー | 全タブを含め入力値を保持。上部に件数と各欄へのリンクをまとめ、そこへフォーカスを移す |
| 非表示タブのエラー | タブに印・件数を出し、まとめのリンクから該当タブを開いて入力欄へ移動する |
| 各欄のエラー | 共通の`.form-error`・`aria-invalid`・`aria-describedby`を利用する |
| 戻る・離脱 | 一覧へ戻るリンクを保存バーへ置く。変更後の未保存離脱は`beforeunload`で警告する |
| 送信失敗・復帰 | 再操作できる状態に戻す。保持方法は商品フォームとバックエンドの仕様を確認する |

タブのARIA・キーボード操作案は[SPEC](../SPEC.md#店舗と送料の案)を参照する。未確定の検証条件を、エラー表示案だけを理由に必須化しない。

## 見た目の案（Kenが画面で調整・決定）

| 対象 | 案・確認内容 |
|---|---|
| 箱 | 商品フォームの白い面・罫線・見出しを基準に、基本情報→配送→送料→送料無料の順に縦に並べる |
| 基本情報 | PCではラベルと入力を横に、タブレットでは縦にする既存フォームの配置を候補にする |
| 規格表示 | 会社選択の近くで、入力欄と区別した読み取り専用の一覧・補助文にする |
| 送料表 | 佐川の13区分ごとに見出しを付け、その下に都道府県の入力欄を並べる。各区分に「この地方に入力」を置く |
| PC／タブレット | 送料欄はPC幅で2〜3列、タブレットで1〜2列。区分のまとまりとラベル・金額・単位が読みやすい配置を画面で調整する |
| タブ | 使用サイズが多い場合の収まり、選択中・フォーカス・エラーの見分け、入力途中の切り替えを確認する |
| 追加料金 | 通常送料の後へ置き、空欄の意味を説明する。冷蔵・冷凍を分けるかは未確定のため、両案を画面で比較する |
| 保存バー | 商品フォームのメイン内stickyを参照。最後の入力欄やフォーカスを隠さず、サイドバーと干渉しないか確認する |

この資料では新たなデザイントークンを確定しない。

## 未確定事項・次に決めること

- 運送会社変更時の使用サイズ・入力済み送料の消去／保持と確認の有無
- サイズ別オン／オフ・使用サイズ解除時の金額保持、一括入力の上書き確認
- 冷蔵・冷凍の追加料金を別欄にするか1欄にするか。ヤマト・佐川は同額であることを踏まえて検討する
- 基本情報の文字数上限・住所の分け方・電話番号の形式、設定の初期値、金額の入力範囲・桁、通常送料の必須案
- 画面名・保存成功後の遷移と文言、ID・日時の表示の要否、送料欄の列数・タブの収まり
- お客様の画面（購入画面）に店舗名を表示するか。表示する場合、店舗名はお客様向けの名前になる
- 「その他」は初期対象外として後回し。独自サイズ・重さ・温度帯条件の設定方法は未確定
- 削除・停止時の商品の扱い、ゆうパックの追加料金区分との対応、規格データの持ち方などは[SPECの未確定事項](../SPEC.md#店舗と送料の未確定事項)を参照する
- パートナー情報画面の制作時期は未定。特定商取引法の表示設定は店舗フォームへ追加しない
