# Client商品一覧 バックエンドへの申し送り

- 作成日：2026-10-19
- 対象：`shop-partner/products.php`（制作用PHP）、`shop-partner/assets/scss/products.scss`
- 作成：フロント（Ken・Codex）

共通の内容は[HANDOFF_CLIENT_COMMON.md](HANDOFF_CLIENT_COMMON.md)を参照。ここには商品一覧固有の内容だけを記載する。仕様の正は`docs/SPEC.md`と`docs/design/CLIENT_PRODUCT_LIST.md`で、内容が食い違う場合は仕様資料を優先し、フロントへ知らせてほしい。

## 1. 制作用PHPのうち、Bladeへ移さないもの

| 対象 | 内容 | Bladeでの扱い |
|---|---|---|
| `$previewState`（`?preview=`）と各`$is…State` | `pager-middle`＝全20ページ中10ページ目、`empty`＝データなし、`no-results`＝検索結果0件、`date-error`＝更新日の逆転エラー | 制作専用の仕組みは共通申し送り§1のとおり移さず、実際のデータ・検索結果・検証結果で分岐する |
| `$listCount`・`$filterNote` | 表示例の件数・対象名 | 実際の件数・検索状態に置き換える |
| 商品6件・986件・ページ番号 | 架空の6商品を掲載し、986件・全20ページ、現在1／10ページ目を表示している | ループと実データに置き換える。6件だけ表示する仕様ではない |
| `assets/images/sample/` | 商品の表示確認用JPEG | 本番の商品画像へ置き換える。確認用画像を商品データとして移さない |

## 2. 商品テーブルの構造と書式

- ページ見出しはh1「商品一覧」だけで、日付・KPIは置かない。規格・商品コード・入稿の有無は列に追加しない
- `.products-scroll`内に`table.products-table`を置き、1商品をtbodyの1行として出力する。スクロールの扱いは共通申し送り§1を参照
- tableの`aria-labelledby="product-list-heading"`で一覧見出しの`<h2 id="product-list-heading">商品一覧</h2>`を参照する。idを変える場合は参照先も合わせる
- theadの各thは`scope="col"`を維持する。列の順序・class・書式は次のとおり

| 列 | class | 出力する内容 |
|---|---|---|
| ID | `.product-id` | システムのID。右揃え・`tabular-nums` |
| 画像 | `.product-image` | 販売用の商品画像。48px角・`width="48" height="48"`・`alt=""`。縮小画像と遅延読み込みは§4を参照 |
| 商品名 | `.product-name` | 長い名前も折り返し、行数を制限しない。リンクにはしない |
| 価格 | `.product-price` | 税込の金額。`¥`＋3桁区切り、右揃え・`tabular-nums` |
| 在庫数 | `.product-stock` | 数字の下に`.stock-note`の文字ラベルを置く。数字・ラベルは右揃えで、ラベルの有無で数字の右端をずらさない |
| 公開状態 | 見出し`.product-publish`、セル内`.publish-state` | 公開／非公開の表示のみ。状態の出し分けは§3を参照 |
| 更新日時 | `.product-updated` | 1つのtimeに機械可読なdatetimeを付け、中を日付`YYYY/MM/DD`・時刻`HH:MM`の2つのspanに分ける。2行・右揃え・`tabular-nums` |
| 編集 | `.product-edit`、中の`.edit-link` | 商品詳細へのリンク。名前・URLは§4を参照 |

更新日時の構造例は`<time datetime="2026-10-19T14:30:00+09:00"><span>2026/10/19</span> <span>14:30</span></time>`。値は実データへ差し替える。表示タイムゾーンは未確定なので、この表示例の`+09:00`を業務仕様の決定とは扱わない。

## 3. 状態ごとの出し分け

共通の空状態の構造と全件表示・条件解除の扱いは[共通申し送り§6](HANDOFF_CLIENT_COMMON.md#6-一覧の表示状態)を参照。

| 画面の状態 | 商品一覧の表示 |
|---|---|
| 通常 | 商品テーブル |
| データなし | 「まだ商品はありません」 |
| 検索結果0件 | 「条件に一致する商品はありません」＋「すべての商品を表示」「条件をクリア」 |
| 更新日の逆転エラー | 詳細検索パネルを開き、開始日・終了日から`#product-date-error`の1つのエラー文を参照する（共通申し送り§5） |

| 一覧内の状態 | 出力する内容 |
|---|---|
| 在庫切れ | `0<span class="stock-note">在庫切れ</span>` |
| 残りわずか | 対象の数値＋`<span class="stock-note">残りわずか</span>`。全商品共通の基準値は未確定で、表示例の3を基準値として実装しない |
| 画像なし | 画像の代わりに`<span class="no-image">画像なし</span>`。現行はグレーの面＋文字。具体的な見た目は調整中だが、画像がないことが文字でも伝わる構造を維持する |
| 公開 | `<span class="publish-state">公開</span>` |
| 非公開 | `<span class="publish-state is-private">非公開</span>`。非公開の行全体を薄くしない |

- 公開状態は表示だけで、ボタン・リンク・切り替え操作を付けない。公開／非公開の変更、入稿の設定・確認は商品詳細で行う
- バッジの見た目は現行Sassを維持する。非公開バッジだけのopacity 0.7とコントラスト例外はKenの決定で、詳細は`DESIGN_TOKENS.md`の「商品の公開状態」を参照
- 在庫管理なし商品の有無・表示、在庫検索の区分の重なり・判定の優先関係は未確定。推測で区分や表示を増やさず、§5・§8を確認してほしい

## 4. 編集リンクと商品画像

- `.edit-link`の`href="#"`は、対象商品の詳細URLへ差し替える。`aria-label`と`title`は両方とも「{商品名}を編集」とし、商品名に合わせて出力する
- 編集アイコンはLucideの`pencil`。20×20のSVG、`aria-hidden="true" focusable="false"`と約40pxの操作領域・ホバー・フォーカス枠を維持する。SVGの書き方は`IMPLEMENTATION_REFERENCE.md`のアイコンの節を参照
- サムネイルは縮小画像を出力し、`loading="lazy"`を付けてほしい。今は表示例のため元画像を使っている。`width="48" height="48"`、`object-fit: cover`と1px枠を維持する
- 商品名が隣にあるためサムネイルの`alt=""`を維持する。画像なしではimgの壊れた表示に任せず、§3の代わりの表示を出力する

## 5. 検索項目と決めてほしい細則

開閉・クリア・初期状態・検索結果の値の復元は[共通申し送り§4](HANDOFF_CLIENT_COMMON.md#4-commonjsの詳細検索とアコーディオン)、入力エラーは同§5を参照。

| 条件 | 表示例のname・value |
|---|---|
| キーワード（商品名・ID） | `keyword` |
| 公開状態 | `publish[]`、`public`／`private` |
| 在庫の状態 | `stock[]`、`available`（在庫あり）／`low`（残りわずか）／`empty`（在庫切れ） |
| 更新日 | `updated_from`・`updated_to` |

- name・valueは表示例。正式名はバックエンドで決めてよい（変えた場合はフロントへ連絡してほしい）
- 詳細検索パネルは`#product-search-panel`。パネル内は公開状態→在庫の状態→更新日の順で、fieldset・legend・各inputのlabelを維持する
- クリア後の先頭inputは「公開」の`#search-publish-public`。更新日の開始日へ固定するために共通JSを変えない
- 更新日の入力は`#product-updated-from`・`#product-updated-to`、共通のエラー文は`#product-date-error`。制作確認の`date-error`は開始日2026-10-20・終了日2026-10-10の逆転例で、文言は「終了日は開始日以降の日付を指定してください」

次の細則は未確定。バックエンドで検討し、フロントと確認してから仕様資料へ反映してほしい。

- キーワードの商品名・IDそれぞれの一致方法（部分一致／完全一致）
- 「在庫あり」に「残りわずか」を含めるか、相互に重ならない区分にするか。0を在庫切れとする際の「残りわずか」との判定の優先関係、在庫管理なしの商品がある場合の検索対象
- チェックが全未選択／複数選択のときの条件と、キーワード・各詳細条件の組み合わせ
- 更新日の片側指定の可否、期間の境界・表示タイムゾーン
- 検索結果0件の「条件をクリア」の遷移先・解除対象は共通申し送り§9を参照

## 6. 並び順

- 更新が新しい順で固定する。並び替えの操作は置かない
- 同じ更新日時の商品の順序は未確定。更新日時自体をいつ更新するかも§8の確認対象
- ページ送りは[共通申し送り§7](HANDOFF_CLIENT_COMMON.md#7-ページ送り)に従う

## 7. JSと読み込み

- 商品一覧はページ固有のJSを持たず、`common.js`だけを使用する。`products.js`は作成していない
- 共通JSの依存class・属性は共通申し送り§3・§4を参照。CSSは`common.css`→`products.css`の順で、読み込みとキャッシュ対策は同§8に従う

## 8. 未確定のまま残っている項目

`docs/SPEC.md`と`docs/design/CLIENT_PRODUCT_LIST.md`の未確定事項も参照。§5の検索細則に加え、バックエンドに関係する確認事項は次のとおり。

- 在庫を管理しない商品（受注生産など）があるか。ある場合は「—」＋読み上げ用の「在庫管理なし」（`.sr-only`）が仮案で、有無・表示とも未確定
- 「残りわずか」の全商品共通の基準値
- 更新日時の更新契機（商品情報の保存時だけか、注文で在庫が減ったときも含むか）、同じ更新日時の商品の順序
- セール価格の有無と、ある場合の一覧表示
- 商品登録への導線を一覧内にも置くか。現行は一覧内には置かず、サイドバーから入る
- 名入れなど文字の入稿の有無と、ある場合の受注一覧での表示位置
- Masterで使う場合の店舗列・店舗での絞り込み
- 共通の未確定事項（条件解除・1ページだけのページ送り）は共通申し送り§9を参照
