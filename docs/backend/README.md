# backend

バックエンド担当者の資料を置くフォルダ。中の構成・ファイル名は担当者が決める。コードはリポジトリのルートの `backend/` に置く。

## 置くもの（例）

- API・ルーティング
- DB設計
- [サーバー側ディレクトリ構成（案）](SERVER_DIRECTORY_LAYOUT.md)
- Laravel・Bladeへの組み込み方法（フロントの制作用PHP・`includes/` の対応先）
- 保存・認証・権限などの実装メモ

## フロントとの約束

- 業務仕様（保存方式、ステータスの選択肢、KPIの集計条件など）の確認・提案は `../QA_BACKEND.md` に書く。`../SPEC.md` 本文と画面資料（`../design/`）への反映はフロントが行う。このフォルダだけに書かない（2026-10-21更新）
- フロントから引き渡すもの・書き方は `../coding/IMPLEMENTATION_REFERENCE.md` を参照
- フロント側の未確定事項は `../SPEC.md` の「未確定事項」と各画面資料の「次に決めること」にまとまっている
- フロントのAI作業（Codex等）はこのフォルダを依頼なく編集しない

## バックエンド仕様の記録・共有ルール

- バックエンド担当者との会話で仕様が確定したら、その都度このフォルダ内の該当資料を更新する。検討中の内容は「案」、未決定の内容は「要確認」と明記し、確定事項と混ぜない
- 他のスレッドでも、このフォルダ内の資料をバックエンド仕様の共有記録として読む。会話だけで決まった内容を残さない
- 資料間に矛盾を見つけた場合は、該当箇所と影響を示してバックエンド担当者に確認し、推測で仕様を統一しない
- このフォルダ外のMarkdownで書いてよいのは、`../QA_BACKEND.md` の「回答（バックエンド）」欄と、末尾に追加する「質問（バックエンド）」だけとする（下記「AI作業のルール」）。書く前に、変更箇所を示してバックエンド担当者に確認する（2026-10-21更新）

## AI作業のルール

2026-10-21、フロントとの取り決め（`../README.md`「追加するときのルール」）に合わせて追加。バックエンドのAI（Claude・Codex等）が作業するときは、最初にこのファイルを読み、今後の作業すべてで次のルールに従う。

### 作業を始める前に

- 作業を始める前に、最新の `ken-work` を取り込む
- 次の資料を読む：`../README.md`（「追加するときのルール」）、`../QA_BACKEND.md`、`../SPEC.md`（冒頭と、作業に関係する節）、このフォルダの資料

### 書いてよい場所

- `docs/backend/`・`backend/`：バックエンドが自由に書いてよい
- `../QA_BACKEND.md`：各項目の「回答（バックエンド）」欄だけ書く。ほかの欄（質問・フロントの案・フロントの対応）は書き換えない
- バックエンドから質問・提案したいときは、`../QA_BACKEND.md` の末尾に新しい番号（次の空き番号）で項目を追加し、「質問（バックエンド）」として書く

### 書き換えないもの

- `../SPEC.md` の本文。仕様について確認・提案したいときは `../QA_BACKEND.md` に書く
- フロントの場所：`docs/design/`・`docs/coding/`・`shop-partner/`・`shop-master/`・`scss/`・`index.html`・`AGENTS.md`
