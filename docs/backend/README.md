# backend

バックエンド担当者の資料を置くフォルダ。中の構成・ファイル名は担当者が決める。コードはリポジトリのルートの `backend/` に置く。

## 置くもの（例）

- API・ルーティング
- DB設計
- [サーバー側ディレクトリ構成（案）](SERVER_DIRECTORY_LAYOUT.md)
- Laravel・Bladeへの組み込み方法（フロントの制作用PHP・`includes/` の対応先）
- 保存・認証・権限などの実装メモ

## フロントとの約束

- 業務仕様（保存方式、ステータスの選択肢、KPIの集計条件など）を決めたら、`../SPEC.md` と該当する画面資料（`../design/`）にも反映する。このフォルダだけに書かない
- フロントから引き渡すもの・書き方は `../coding/IMPLEMENTATION_REFERENCE.md` を参照
- フロント側の未確定事項は `../SPEC.md` の「未確定事項」と各画面資料の「次に決めること」にまとまっている
- フロントのAI作業（Codex等）はこのフォルダを依頼なく編集しない

## バックエンド仕様の記録・共有ルール

- バックエンド担当者との会話で仕様が確定したら、その都度このフォルダ内の該当資料を更新する。検討中の内容は「案」、未決定の内容は「要確認」と明記し、確定事項と混ぜない
- 他のスレッドでも、このフォルダ内の資料をバックエンド仕様の共有記録として読む。会話だけで決まった内容を残さない
- 資料間に矛盾を見つけた場合は、該当箇所と影響を示してバックエンド担当者に確認し、推測で仕様を統一しない
- `../SPEC.md` などこのフォルダ外のMarkdownに反映が必要な場合は、変更箇所を示して、その都度バックエンド担当者に確認してから更新する。上記「フロントとの約束」にある反映も、この確認後に行う
